01 / 产品概述

什么是 SmartAsk

SmartAsk 是帮助企业业务人员用自然语言直接查询经营数据的 AI 数据应用平台。它将分散在数据库、报表与表格中的经营指标，收敛为统一的数据集知识库与口径规则；用户只需提出业务问题，系统便自动完成从意图识别到报告呈现的完整链路，把「提需求 → 等排期 → 对口径 → 出报表」的数小时乃至数天，压缩到秒级流式返回。

与通用 AI 问答的本质区别：每次回答都被企业自己的数据字典、口径规则与权限体系约束——可复核、可审计、可下钻，而非模型的即兴输出。

自然语言入口

无需 SQL、不懂表结构，日常业务语言直接提问；支持 8 轮上下文追问与指代消解，题干序号、口语化表达与残缺问法自动清洗补全。

四 Agent 引擎

路由、生成、复核、解读分工协作，每层独立校验，避免大模型直出 SQL 的不可控；高频问题走确定性规则，复杂问题交给模型泛化。

可解释的经营分析报告

结构化输出核心结论、KPI 卡片、明细看板、图表与下钻结构，并保留完整执行轨迹与 SQL——每个答案都能讲清「数是怎么来的」。

03 / 行业痛点

经营分析的四道坎

这些问题在制造业、消费品、零售与项目型组织中高度相似，长期无法被传统报表与 BI 工具解决。

响应慢：一个问题等上几天

业务问题往往发生在晨会、周会、经营复盘现场，但取数依赖数据团队排期。提需求、对口径、写 SQL、出报表，一个简单问题耗时数小时到数天，会议现场永远拿不到答案；等数据终于出来，决策窗口往往已经过去。

COST决策被数据响应时间拖慢，管理层被迫用滞后的数据做判断。

口径乱：同题多答

「达成率」在不同事业部的层级、字段与统计方式各不相同。没有统一入口与确认机制时，不同人查出来的数不一致，跨部门对不上账。

COST会议时间消耗在对数上，数据公信力受损。

门槛高：两张皮

业务知道自己想问什么，却不知查哪张表哪个字段；数据人员懂技术，却未必理解问题背后的管理意图；BI 工具需要学习拖拽建模，自助分析停留在口号。

COST数据团队被重复取数淹没，无暇做高价值分析。

不沉淀：人走了，口径就没了

分析口径、SQL 逻辑与业务经验散落在个人电脑与私人脚本里。同一类问题每次重新解释、重新写、重新对，知识无法沉淀到组织层面，换人就要重来，同样的问题一再发生。

COST分析能力随人员流动而流失，同样的口径错误反复发生。
THE HIDDEN COST

会议现场拿不到答案，
是经营分析最大的隐性成本。

响应每慢一天，就多一天凭经验拍板的风险。

05 / 分析场景

六大经营分析报告场景

每个场景有独立的识别规则与报告契约，不是同一个模板的换皮。

SCENE / DETAIL

详情查询

单主体指标查询，如「东部分公司本月达成率怎么样」。返回核心结论 + KPI 卡片 + 下级组织明细，并默认带出直接下级支持下钻——单个对象不是终点，而是探索的起点。OUTPUT → 结论 + KPI + 明细 + 图表 + 下钻

SCENE / RANKING

排名筛选

TopN、最好 / 最差，如「哪些分公司达成率低于 30%」。OUTPUT → TopN 清单 + 指标对比

SCENE / COMPARATIVE

对比分析

多主体并排比较，如「山东和河南的业绩对比如何」。OUTPUT → 并排指标 + 差异分析

SCENE / DRILLDOWN

组织下钻

沿组织层级逐层展开，如「东部下面各代表处表现如何」。OUTPUT → 层级展开 + 逐级明细

SCENE / FILTER

条件过滤

金额、阈值、渠道等条件筛选，自动完成单位换算。OUTPUT → 条件清单 + 阈值高亮

SCENE / DIAGNOSTIC

诊断分析

风险、缺口与异常归因，如「为什么这个月业绩下滑」。围绕达成率异常节点输出问题诊断与改进建议，而不只是罗列数字。OUTPUT → 归因 + 诊断 + 改进建议

07 / 可信与合规

企业敢用，比模型能答更重要

问数产品最大的风险不是答不上来，而是「一本正经地给出错误答案」。工程层面的五道防线：

DEFENSE_01 · DISAMBIGUATION

口径不确定时，先问再做

路由打分采用显式阈值：候选得分足够高且领先第二名足够多时自动选择；分差过小或次名得分过高时，主动向用户弹出口径确认卡片。宁可慢一步，不给错误答案——对企业经营分析来说，口径正确比回答速度更重要。

score ≥ 80 && margin ≥ 20AUTO_PICK
margin < 15 || runner-up ≥ 55NEED_CONFIRM
route < 65 || output < 62LOW_CONFIDENCE
DEFENSE_02 · READ_ONLY

只读 SQL + 独立复核

只允许查询类 SQL，禁止写入、修改与删除；Agent3 专职复核只读安全、字段合理性、统计口径与组织路径，发现问题即进入修复链路，绝不带病执行。

DEFENSE_03 · PERMISSION

四层权限管控

路由权限（能进哪些页面）、功能权限（能用哪些功能）、数据集权限（public / restricted / org_tree / disabled 四种模式）、行级权限（能看到哪些数据行），四层隔离。

DEFENSE_04 · TRACEABLE

全过程可追溯

前端实时展示执行轨迹（理解口径 → 生成 SQL → 校验 → 执行 → 报告），可展开完整 SQL、耗时与 Token 用量；后端全量落盘执行轨迹与系统审计日志。

DEFENSE_05 · CONTRACT

确定性报告契约

ReportSpec v2：后端输出结构化报告协议，前端按契约渲染 KPI、表格、图表与下钻结构，避免大模型自由生成页面导致的版式漂移与指标错配，结果可测试、可回归、可复用。

08 / 应用场景

真实问句，真实返回

以下问法均来自真实回归用例。已验证数据集：消费者事业部任务达成（分公司 / 城市分公司）、商用事业部经营数据（分公司 / 代表处 / 业务部 / 业务代表）、飞书电商事业部经营预算（业务部 / 细分业务 / 业务承接人）。

东部分公司本月达成率怎么样？
返回核心结论 + 达成率 KPI 卡 + 下级组织明细，按报告契约输出亮点分析与问题诊断。
哪些分公司达成率低于 30%？
识别消费者与商用两个事业部均可回答，先弹出口径确认卡片再执行，避免答非所问。
消费者事业部哪些分公司年度开单金额低于 3000 万？
把「3000 万」正确换算为数据库金额口径后过滤，返回命中分公司清单及对应指标。
