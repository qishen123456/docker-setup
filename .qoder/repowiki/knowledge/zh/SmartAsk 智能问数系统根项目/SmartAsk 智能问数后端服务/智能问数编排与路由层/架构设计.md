本模块由三层协作构成：
- 控制器层（`backend/controllers/ask_flow.py`、`smart_chat.py`）：分别注册 `/api/admin/ask-flow` 和 `/api/smart-chat/*` 两个 Blueprint，统一通过 `auth_store.get_current_user` 鉴权、`feature_flags.feature_available` 功能开关校验、`system_log_store.log_event` 记录审计。
- 路由决策层（`backend/ask_flow/controller.py` + `contracts.py`）：`AskFlowController` 单例根据 `defaultFlow`、`advancedEnabled`、`advancedRoles`、`datasetPolicies` 及环境变量决定调用 `basic_ask_service` 还是 `advanced_ask_service`，并在异常时按 `fallbackToBasicOnError` 回退；`AskRequest`/`ConfirmRequest`/`FlowDecision` 定义跨子模块的契约。
- 能力子模块：`memory.short_term_memory.ShortTermMemoryStore` 以 session_id 为键维护 TTL+max_rounds 的追问历史，提供 `resolve_followup` 将条件类追问改写为带金额单位与 SQL 提示的完整问题；`disambiguation.llm_arbiter.DisambiguationArbiter` 结合候选数据集评分快照与对话历史，通过 LLM 仲裁或规则自动选择/生成确认选项，并由 `option_builder` 与 `scoring` 辅助。
- 数据流：控制器 → `ask_flow_controller.ask/confirm_by_boss` → 选中的 engine → 内部使用 `ShortTermMemoryStore` 与 `DisambiguationArbiter` → 返回结构化结果（含 `requires_confirmation`、`confidence`、`trace_events`），再由控制器统一打日志与 SSE 流式推送。
