## 三、三大关键发现

### 1. 方言/腔调容错意外地强（好消息）
东北话、广东话、四川话、河南话、上海话、文言腔、新人腔、反问腔——**全部高容错**。说明现有 Agent1 + 别名模糊匹配 + LLM 对自然语言变体的消化能力已经不错，**P1 不需要在这些类型上花力气**。

### 2. 三大真实短板（P1 重点）
- **拼音首字母（NB/XB/DJ）**：不仅漏，还会**答错**（DIRECT_WRONG）——把首字母映射到错误实体。这是**最高优先级**，因为答错比漏网危害大。
- **中英混写（JD/tmall/dongbu）**：完全没处理，0 行漏网。
- **超短/极端/层级（两字简写/极端筛选/层级跳跃）**：规则+LLM 都接不住的边界。

### 3. 人名同音错被确认卡接住，而非纠正卡（链路长）
「靳锋」这类人名同音错，走的是**数据集确认卡**（用户先选数据集）→ 才可能看到纠正，链路太长。这正是 P1 LLM 主判该**前置拦截**的——在路由层之前就识别"靳峰=靳锋"直接给纠正。

## 四、P1 LLM 主判的 prompt 改进重点（基于短板数据）

按短板优先级，P1 守门员的 prompt 应重点覆盖：

1. **拼音首字母映射**（最高优先）：建立"首字母 → 实体"映射表（NB→南部分公司、XB→西部分公司、JD→京东直营、DJ→丁杰等），防止答错。
2. **中英混写**：英文/拼音 → 中文实体映射（dongbu→东部、JD→京东、tmall→天猫）。
3. **超短输入**：两字简写（商用→商用事业部）需要结合上下文/常用实体猜。
4. **人名同音前置**：在路由层之前识别 2 字人名同音错（靳峰→靳锋），直接纠正卡而非走数据集确认。
5. **极端筛选/层级跳跃/否定排除**：语义层面的路由兜底（当前漏网）。
