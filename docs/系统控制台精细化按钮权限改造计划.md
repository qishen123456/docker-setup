# 系统控制台精细化按钮权限改造计划

## 1. 当前问题

当前控制台第一版把“左侧导航入口”和“页面内按钮”混在一个开关列表里，导致三个问题：

- 阅读顺序乱：导航、按钮、体验开关、危险操作混在一起。
- 控制粒度不清：关闭一个按钮时，容易误以为对应导航页也会消失。
- 页面排布松散：折叠后仍存在大块空白，一行只展示少量信息，管理效率低。

后续重构目标：先控制左侧导航栏，再按每个导航页面控制该页面内部按钮。

## 2. 新控制台信息架构

控制台页面分为两层。

第一层：左侧导航栏控制

- 独立板块，放在页面最上方。
- 一行展示多个导航开关，建议 3-4 个一行。
- 每个导航项只展示：导航名称、开放角色、显示/隐藏开关。
- 只控制左侧菜单是否可见，不控制页面内按钮。

第二层：各导航页内部按钮控制

- 按导航模块分组，例如：
- 智能分析工作台
- 智能体编排配置
- 数据资产管理
- 数据连接管理
- 模型服务配置
- 报告模板配置
- 飞书数据同步
- 迁移发布管理
- 员工权限配置
- 系统控制台

每个模块内部用紧凑网格展示按钮权限。

- 每个按钮卡片只展示：按钮名称、开关、角色选择。
- 说明文字不直接铺开，改成 tooltip 或 hover 查看。
- 每行展示 3-4 个按钮控制项。
- 默认只展开高频模块，其余模块折叠后只保留一行模块标题，不留大白块。

## 3. JSON 结构建议

继续使用 JSON，不引入数据库表。

建议将现有扁平 `features` 兼容保留，但新增元数据字段，前端按字段自动分组：

```json
{
  "version": 2,
  "updated_at": "",
  "features": {
    "nav_smart_ask": {
      "label": "智能分析工作台",
      "module": "navigation",
      "module_label": "左侧导航栏",
      "kind": "navigation",
      "enabled": true,
      "roles": ["super_admin", "admin", "user"],
      "order": 10
    },
    "runtime_import": {
      "label": "导入运行态包",
      "module": "runtime_migration",
      "module_label": "迁移发布管理",
      "kind": "button",
      "enabled": true,
      "roles": ["super_admin"],
      "order": 30,
      "risk": "high"
    }
  }
}
```

关键点：

- `kind=navigation`：只控制左侧导航。
- `kind=button`：只控制页面内部按钮。
- `module`：归属页面模块。
- `module_label`：控制台展示分组名。
- `order`：控制显示顺序，避免东一块西一块。
- `risk=high`：高风险按钮可用红色标识，例如删除、导入、覆盖、清空。

## 5. 控制台 UI 方案

### 5.1 顶部区

保持短小：

- 标题：系统控制台
- 副标题：功能入口与按钮开放控制
- 操作：刷新、恢复默认、保存配置

不要再放大块说明。

### 5.2 导航栏控制区

样式：

- 独立卡片。
- 标题：左侧导航栏。
- 网格布局，每行 4 个导航项。
- 每个导航项是一条横向小卡：名称 + 角色 + 开关。

示例：

```text
左侧导航栏
[智能分析工作台  用户/管理员/超管  开] [数据资产管理  管理员/超管  开] [模型服务配置  管理员/超管  关]
```

### 5.3 页面按钮控制区

样式：

- 标题：页面按钮权限。
- 按导航页分组。
- 每个分组是 `el-collapse` 或自定义折叠面板。
- 折叠态只显示：模块名、开放按钮数、总按钮数。
- 展开态内部使用 3-4 列紧凑按钮网格。

示例：

```text
页面按钮权限
数据资产管理  6/8 开放
[新建数据集 开  管理员/超管] [保存书架内容 开  管理员/超管] [删除数据集 关  超管]

迁移发布管理  3/6 开放
[导出运行态包 开] [预检导入 关] [确认导入 关] [手动备份 开]
```

### 5.4 高风险按钮标识

以下按钮加风险标识：

- 删除类。
- 清空类。
- 正式导入。
- 覆盖配置。
- 替换模式。
- 重置密码。

视觉上用小红点或 `高风险` 标签，不要大面积红色。

## 6. 前端接入方式

新增统一能力：

```js
isFeatureEnabled('runtime_import_confirm')
```

页面中重要按钮使用：

```vue
<el-button v-if="isFeatureEnabled('runtime_import_confirm')">确认导入</el-button>
```

注意：

- 导航入口只读取 `kind=navigation`。
- 页面按钮只读取 `kind=button`。
- 页面按钮关闭时，不影响导航页显示。
- 如果按钮关闭后页面里还有相关输入控件，应同步禁用或隐藏，避免用户填了但不能提交。

## 7. 后端接入方式

第一阶段只做前端隐藏。

第二阶段补后端强校验，避免用户绕过前端直接调用接口：

- 运行态导入接口检查 `runtime_import_confirm`。
- 员工删除接口检查 `employee_delete`。
- 数据源删除接口检查 `datasource_delete`。
- 数据集删除接口检查 `dataset_delete`。

## 8. 实施步骤

### 阶段 1：清理现有控制台

- 回收当前散乱分类。
- 保留已有开关值，但按新字段 `kind/module/order` 重新归类。
- 控制台页面改成两块：左侧导航栏、页面按钮权限。

### 阶段 2：补全按钮清单

- 根据本文第 4 节建立默认 JSON。
- 每个按钮都有稳定 key，不再临时命名。
- 高风险按钮加 `risk=high`。

### 阶段 3：页面接入

优先接入生产风险高的页面：

1. 迁移发布管理。
2. 员工权限配置。
3. 数据资产管理。
4. 数据连接管理。
5. 模型服务配置。
6. 飞书数据同步。
7. 报告模板配置。
8. 智能分析工作台。

### 阶段 4：后端兜底

- 给删除、导入、覆盖、重置等高风险接口加后端开关校验。
- 返回明确错误：`该功能已由系统控制台关闭`。

### 阶段 5：测试

- 超管登录后能看到控制台。
- 关闭导航，只隐藏左侧菜单，不影响其他模块按钮。
- 关闭页面按钮，只隐藏按钮，不隐藏导航。
- 关闭运行态导入按钮时，迁移发布管理仍然显示。
- 普通用户不看到管理类导航。
- 管理员只能看到自己角色开放的功能。
- 保存后刷新页面仍生效。
- 导出运行态包包含功能开关。

## 9. 推荐默认分组

默认展开：

- 左侧导航栏。
- 迁移发布管理。
- 员工权限配置。

默认折叠：

- 数据资产管理。
- 数据连接管理。
- 模型服务配置。
- 飞书数据同步。
- 报告模板配置。
- 智能分析工作台。

这样控制台初始高度会明显变短，页面不会出现大白块。
