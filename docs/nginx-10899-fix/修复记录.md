# 2026-08-21 飞书登录 10899 反代 502 修复记录

## 现象

飞书登录入口 `https://bifine.angelgroup.com.cn:10899` 返回 502 Bad Gateway。

## 链路拓扑（本次确认）

```
浏览器/飞书
  → https://bifine.angelgroup.com.cn:10899
  → DNS 解析到 10.2.33.23（前置网关，TLS 在此终结）
  → 明文 HTTP → 10.2.7.81:10899（本机 BT panel nginx）
      ├─ /api/ → 127.0.0.1:5002（smartask-backend 容器）
      └─ /     → 127.0.0.1:8888（smartask-frontend 容器）
```

关键点：**本机 10899 必须监听明文 HTTP**，TLS 由网关终结。

## 根因（两层叠加）

1. **stream 块抢端口**：`/www/server/nginx/conf/nginx.conf` 残留 stream TCP 直转发
   （`listen 10899; proxy_pass 10.2.7.81:8888`，旧方案），与 `smartask.conf`
   的 10899 HTTP 监听冲突。所有 `nginx reload` 均报
   "bind() to 0.0.0.0:10899 failed (98: Address already in use)" **静默失败**，
   线上一直运行旧 master（15:22 启动）的过期坏配置 → 502。
2. **误设 ssl 监听**：修复中曾将 `smartask.conf` 改为 `listen 10899 ssl`，
   但网关回源是明文 HTTP，直连验证返回 400 "plain HTTP request was sent to
   HTTPS port"，确认本机不应启 ssl。

## 修复动作

| 文件（线上实际路径） | 改动 |
|---|---|
| `/www/server/nginx/conf/nginx.conf` | 注释掉 stream 块（10899 TCP 直转发），保留说明 |
| `/www/server/panel/vhost/nginx/smartask.conf` | `listen 10899 ssl` → `listen 10899`（明文），证书两行注释保留 |

改完执行 `nginx -s stop && nginx` 完全重启（**reload 无法释放旧端口，必须 stop+start**）。

本目录内 `nginx.conf` / `smartask.conf` 即修复后生效版本的留档副本。

## 验证结果

- `https://bifine.angelgroup.com.cn:10899/`（经网关）→ 200
- `GET /api/auth/feishu/login-url` → 200，redirect_uri 正确指向
  `https://bifine.angelgroup.com.cn:10899/api/auth/feishu/callback`
- docker 前端(8888)/后端(5002)/PG 容器 healthy；服务器出网正常（open.feishu.cn 可达）

## 注意事项（运维约定）

- 不要再往 nginx.conf 的 `stream{}` 里加 10899 的 server 块
- 更换 10899 监听方式时必须完全重启 nginx，reload 会静默失败并保留旧配置
- 证书 `/www/server/nginx/conf/ssl/smartask.crt`（CN=bifine.angelgroup.com.cn，
  有效期 2026-08-10 ~ 2027-08-10）当前未使用；如改为本机终结 TLS 再启用
- 修改前的原始文件备份：
  `nginx.conf.bak.20260821-fix10899`、`smartask.conf.bak.20260821-fix10899`（均在原目录）
