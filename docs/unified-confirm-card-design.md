# 统一确认卡设计（先锁问题 · 再锁范围 · 唯一不弹）

> 2026-08-30 定稿。来源：用户交互模型讨论 + 当日 nb/上海/排名三个实测案例。
> 相关代码：`backend/four_agent_ask.py`（route_with_agent1 节点索引块）、
> `backend/disambiguation/initials_guardrail.py`（缩写映射）、
> `backend/disambiguation/parse_spans.py`（解析条）、`frontend/src/views/SmartAsk.vue`（确认卡/纠正条 UI）。

## 一、交互模型

用户心智只有一条线：**系统先跟我确认"问句"，问句定了还说不清范围，才跟我确认"范围"**。

```
用户提问
   ↓
① 锁问题（问句确认卡）：系统给"你是不是想问X"候选 + 用户可自由改
   ↓ 问句确定后判断
   ├─ 主体唯一（一个节点/一个数据集）→ 直接执行，不再弹任何卡
   └─ 主体仍歧义（范围词：各分公司/上海/业绩排名）→ ② 锁范围（确认卡）
```

**跳层规则（核心）**：①选的问句如果已经消解了范围歧义，②自动跳过。
例：nb → ①给出"南部分公司的业绩 / 北部分公司的业绩"两个完整问句候选，用户一点，
新问句自带唯一节点，直接出答案——**一次交互结束，没有第二张卡**。

## 二、三种确认面的分工

| 确认面 | 管什么 | 阻断性 | 现状 |
|---|---|---|---|
| 解析条（我理解为：在[X]里查[Y]的[Z]） | 常显回显系统理解，随时可改 | 非阻断 | 已上线（含确认卡场景的理解条） |
| 问句确认卡（错字卡/守门员条） | ①锁问题：chips=完整问句候选 + 自由输入框 | 错字卡阻断 / 守门员条非阻断 | 已上线（自由输入框 2026-08-30 加） |
| 统一节点确认卡 | ②锁范围：对象多节点/多数据集歧义 | 阻断 | 已上线（node_index_ambiguous） |
| 数据集确认卡 | 兜底：无具体对象的纯数据集歧义 | 阻断 | 存量保留，降级为兜底 |

**一次提问最多弹一张卡。** 多歧义同时命中时按仲裁优先级只弹一种（见第五节）。

## 三、统一节点确认卡（主场景，替换"先选数据集"）

### 触发时机

对象在**多节点/多数据集**歧义时触发——不是"选数据集"，是"这个对象到底是哪个节点"：

- 「nb的业绩」→ 南部**分公司** / 北部**分公司**（缩写撞车组）
- 「上海的业绩」→ 消费者·上海**城市公司** + 商用·上海**代表处**（跨数据集字面撞车）
- 「东部分公司的业绩」→ 唯一节点 → **不弹**（直锁）

### 候选生成（全部来自书架，不硬猜）

1. 书架（`config/dataset_node_index.json` 的 `flat_alias_index`）查出对象命中的精确节点：
   node_name + node_level + dataset_id，**节点带类型**（城市公司/代表处/分公司）。
2. 缩写撞车组（拼音推不出的，如 nb→北部=bb 推不出）由人工精排表
   `config/abbreviation_aliases.json` 收录，值支持列表：`"nb": ["南部分公司", "北部分公司"]`。
3. **最长别名优先**：题干已被长别名精确到节点（"上海城市公司"）时，丢弃短前缀
   （"上海"）带出的兄弟节点，不过度确认。
4. 同数据集撞车时标签只留节点名，数据集名放描述行（`商用事业部开单金额 · 分公司层级`）；
   跨数据集撞车标签带数据集前缀。
5. 撞车组**不挂"推荐"角标**——真歧义时系统没有倾向，挂推荐是误导。

### 提交语义（关键决策）：眼睛看到问句，手里提交结构

- 选项**显示**贴近用户语言（节点名/问句样式），但**提交走结构化**：
  `dataset_ids + resolved_subject_name + resolved_subject_level` → confirm_by_boss 直锁执行，
  不重跑 LLM 路由（快、确定、零漂移）。已实测：nb 选北部 → row_count=7、主体正确、无二次弹卡。
- 用户要"改"的诉求由卡上的**自由输入框**兜底（"都不合适？补充说明/输入你想问的"），
  输入内容当新问题走主链路全管线。
- 若候选用问句样式展示（"南部分公司的业绩"），生成规则是**原句挖掉主体片段、原位填节点全名**，
  保留用户原指标词（"nb的达成率" → "南部分公司的达成率"，不是模板重写为"的业绩"）。
  复用 `initials_guardrail.build_initials_preview` 的 overlap 去重逻辑。

## 四、数据集确认卡降级为兜底

只在**无具体对象的纯数据集歧义**时保留：
"各分公司业绩排名"（分公司跨消费者/商用两个数据集，没有可锁定的节点）→ 选数据集。

对象歧义场景（上海/nb）一律走统一节点卡，不再先弹数据集卡。

**不在本次替换范围**：成员集合确认、组织树范围确认、相似数据集确认——保持现状。

## 五、仲裁优先级与豁免

同一问题可能同时命中多类歧义，定死优先级，一次只弹一张卡：

```
锁问题类（错字 early_clarify / 守门员纠正）
  > 节点歧义（统一节点卡）
  > 纯数据集歧义（数据集兜底卡）
```

**豁免红线（防回归）**：
- **多主体/对比意图豁免**："东部和南部的对比"各命中一个节点，distinct=2 属正常对比，
  不许弹卡（qa 冒烟 C1 用例守门）。
- 追问链（"那北部呢"）走上下文继承，不重新弹卡。
- fail-open：消解/索引任何异常 → 不弹卡，走原流程。

## 六、与解析条闭环

```
统一确认卡（执行前一次选对）
   ↓ 执行
解析条：我理解为：在[消费者事业部]里查[上海城市公司]的[开单金额]
   ↓ 槽位可点改（已上线）
想换成"上海代表处"或"达成率"？点一下编译新问句重跑
```

确认卡管"执行前一次选对"，解析条管"执行后可微调"，确认卡场景也出理解条
（`_build_confirmation_parse_bar`，2026-08-30 加）——用户确认前就能看到系统理解了什么。

## 七、当日已落地的件（本方案的地基）

- 节点级确认卡：`route_with_agent1` 同数据集多节点出卡 + 最长别名优先 +
  描述带数据集·层级 + 撞车组措辞「可对应多个节点」
- 精排表列表值：`nb: [南部分公司, 北部分公司]`（initials_guardrail.map_token）
- 确认卡理解条 + 纠正条/错字卡自由输入框
- 排名 both 场景标签修复（前端 rankSides 识别"第一" + 后端 rank_request_spec
  负向后顾 + 有效 rank_sides/direction 回写 query_intent）

## 八、落地路径（剩余工作）

1. 统一卡的问句样式展示（如需）：选项 label 从节点名升级为完整问句，提交仍走结构化
2. 缩写撞车改走问句候选卡（如决定①层就用问句形态）：路由层 initials 撞车时
   返回问句候选而不是节点卡
3. 守门员候选与书架对齐：守门员纯 LLM 世界知识（"北部"）改为书架候选优先，
   避免推荐书架不存在的节点

## 九、验收标准

- nb的业绩 → 一张卡：南部/北部候选（无推荐角标）+ 理解条 + 自由输入；选定直接出数
- 上海的业绩 → 城市公司/代表处节点卡（带数据集·类型描述）
- 上海城市公司的业绩 → 不弹卡（最长别名直锁）
- 东部分公司的业绩 → 不弹卡（唯一节点直锁）
- 各分公司业绩排名 → 数据集兜底卡（存量行为，qa R2 守门）
- 东部和南部的对比 → 不弹卡（对比豁免，qa C1 守门）
- 排名第一和倒数第一的业务员对比 → 前1后1标签正确（韩晓娇第1名/李文强倒数第1名）
