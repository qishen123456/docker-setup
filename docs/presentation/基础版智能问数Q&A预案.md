# 基础版智能问数 Q&A 预案（专业版）

> 配套专业版演讲稿使用，覆盖业务、技术、安全、交付、演进五类常见问题  
> 回答口径：先给结论，再给机制，最后给证据或落地建议

---

## 一、业务与效果类

### Q1： SmartAsk 基础版的准确率怎么样？

**参考回答**：

基础版已经能稳定回答常见经营分析问题。准确率取决于三个因素：数据集元数据质量、Golden SQL 覆盖度、问题表述清晰度。

系统通过三层策略提升稳定性：
- **Golden SQL 直执行**：高频问题直接命中人工沉淀口径，基本零偏差；
- **规则 SQL 兜底**：中频模式走确定性规则，减少模型随机性；
- **Agent2 动态生成 + Agent3 复核**：新问题由大模型生成，再经过安全、字段、口径复核。

如果路由不确定，系统会主动停下来让用户确认，而不是给错误答案。这是基础版和中阶版的分界：基础版先保证“不会乱答”，中阶版再进一步提升“一次答对”的比例。

**证据**：当前四类报告场景识别测试全部通过，报告契约健康度 100/100。

**落地建议**：交付时先用 20–30 个高频问题做验收，确保这些问题准确率达标后再扩大范围。

---

### Q2： 它能替代 BI 工具吗？

**参考回答**：

基础版不是替代 BI，而是降低 BI 的使用门槛，补充 BI 的“最后一公里”。

BI 工具适合需要深度探索、复杂看板、长期监控的场景；SmartAsk 适合“我有一个具体问题，想快速得到答案”的场景。两者可以共存：业务人员先用 SmartAsk 快速问数，复杂分析再交给 BI 或数据团队。

可以把 SmartAsk 理解成 BI 前面的“自然语言入口”和“口径沉淀层”。

---

### Q3： 业务人员需要培训多久才能上手？

**参考回答**：

基础版的学习成本很低。界面只有一个输入框，像聊天一样输入问题即可。

通常 10 分钟就能完成首次使用培训，包括：怎么提问、怎么看报告、怎么恢复历史。真正需要花时间的，是让用户理解“哪些问题适合问”，以及熟悉系统推荐的问题示例。

对于安吉尔这类组织层级复杂的企业，可能还需要 1–2 次培训，帮助用户理解不同口径之间的区别，比如“出货”和“零售”的区别。

---

### Q4： 可以问多复杂的问题？

**参考回答**：

基础版适合以下几类问题：
- 单指标查询：达成率、销售额、出货量
- 排名对比：哪个区域/产品/渠道最好
- 时间趋势：本月相比上月变化
- 组织下钻：某大区下面各城市/经销商的表现

不适合的问题包括：跨多个数据集复杂关联、需要大量业务假设的预测、超出已有数据范围的开放性问题。这类问题可以作为后续进阶能力逐步支持。

---

### Q5： 报告里的数字口径从哪里来？怎么保证一致？

**参考回答**：

口径一致性由三层机制保证。

第一层是**数据集知识层**。每个数据集都维护字段字典、LLD、Golden SQL，明确每个指标怎么算。

第二层是**报告契约层**。`dataset_report_config` 定义了标准输出列、指标、层级、风险阈值和信号灯规则，Agent2 生成 SQL 时必须遵循这些约束。

第三层是**复核层**。Agent3 会检查 SQL 输出列是否符合契约要求，不符合会返回修复或说明。

也就是说，同一个指标在不同问题中，只要命中同一个数据集和报告契约，计算口径就是一致的。

## 二、技术与架构类

### Q6： 支持哪些数据源？

**参考回答**：

当前 Docker 默认使用 PostgreSQL。配置层保留了 SQLite、MySQL、PostgreSQL、SQL Server 的扩展入口。

基础版交付时，数据源由交付方提前配置好，用户无感知。如果后续需要接入其他数据源，可以在进阶版中通过数据连接管理功能扩展。

---

### Q7： 用的是什么大模型？可以换吗？

**参考回答**：

系统支持 OpenAI-compatible API，可以配置通义千问、DeepSeek、私有模型等。

基础版中模型由交付方统一配置，用户不直接选择。当前版本前端已经支持模型选择器（Auto / 手动指定），但基础版建议保持默认，减少用户干扰。

---

### Q8： 基础流程和进阶流程是什么关系？

**参考回答**：

两者是“双流程并行、统一输出”的关系。

用户从前端发起问题，统一进入 `/api/smart-chat` 或 `/api/smart-chat/stream`。后端的 `AskFlowController` 根据配置、用户角色、数据集策略决定本轮走基础流程还是进阶流程。

基础流程是稳定的四 Agent 引擎，适合 80% 的常规问题。进阶流程通过 Skill 链路处理更复杂的需求，比如路由透明化、资产解释、Pandas 二次加工、结果自检等。进阶流程异常时会自动回退到基础流程。

两套流程最终都输出统一的结果契约：`dataset_results`、`report_spec`、`analysis`。前端不需要知道后端用了哪套流程。

---

### Q9： 什么是 ReportSpec v2？为什么不让大模型直接生成报告？

**参考回答**：

ReportSpec v2 是后端输出的确定性报告协议。它定义了报告的完整结构：KPI、章节、图表、下钻结构、数据来源等。

不让大模型直接生成 HTML 或报告，是因为那样不可控、不可解释、不可复现。通过 ReportSpec，我们可以保证：
- 同一个问题每次展示结构一致；
- 报告可以追溯到 SQL、数据集、字段和口径；
- 前端只需要按协议渲染，不需要自己推断页面结构。

报告的具体业务洞察由 Agent4 生成，但页面结构由 `report_spec_builder` 根据报告契约和问题场景确定性生成。

---

### Q10： 如果 SQL 执行失败怎么办？

**参考回答**：

系统有两层保障。

第一层是事前复核：Agent3 会检查 SQL 是否只读、字段是否存在、JSONB 字段读取是否合理等，拦截大部分明显问题。

第二层是事后修复：如果数据库执行仍然报错，系统会捕获真实错误，由 Agent2Repair 基于错误信息和 DDL 尝试自动修复，并再次经过 Agent3 复核和执行。如果仍然失败，会返回优雅降级结果，保留错误说明和诊断信息，而不是直接崩溃。

## 三、安全与权限类

### Q11： 数据安全怎么保证？会不会泄露未授权数据？

**参考回答**：

基础版做了五重防护：

1. **数据集访问权限**：用户只能查询自己被授权的数据集；
2. **组织提及权限检查**：问题中提到未授权组织时直接拦截；
3. **组织行级权限**：执行前自动在 SQL 外层包一层组织范围过滤；
4. **SQL 只读执行**：禁止任何增、删、改操作；
5. **异常自动修复 + 优雅降级**：减少因错误导致的意外输出。

即使 Agent2 生成了包含未授权组织的 SQL，执行前的行级权限过滤也会把它拦截掉。

---

### Q12： 大模型会不会看到我们的全部数据？

**参考回答**：

不会。大模型主要接触的是元数据，比如字段名、字段含义、样例 SQL、问题表述，而不是真实业务数据。

SQL 执行是在本地数据库完成的，执行结果中的一部分会进入 Agent4 做业务解读，但这个过程是可控的。后续高阶版还可以进一步做数据脱敏和审计。

---

### Q13： 能否做到不同角色看到不同数据？

**参考回答**：

可以。基础版支持数据集级权限和组织行级权限。

- 大区总监可以看到大区及下属数据；
- 省区经理只能看到本省数据；
- 城市主管只能看到本市数据。

更细粒度的 RBAC、用户组、数据权限矩阵，可以在中阶版和高阶版中进一步开放。

---

### Q14： 行级权限落地复杂吗？需要改造业务表吗？

**参考回答**：

不一定需要改造业务表，要看当前数据现状。

如果业务表已经有组织编码，直接配置即可。如果只有组织名称，可以作为过渡方案。如果组织关系复杂或缺少编码，我们推荐新增一张业务组织映射表，把业务对象和组织树节点关联起来。

整体路线是：先明确每个数据集的组织口径，再配置权限映射，最后做权限预检验证。

## 四、交付与落地类

### Q15： 部署需要多久？需要准备什么环境？

**参考回答**：

推荐 Docker 一键部署。准备环境：
- 一台装有 Docker Desktop 或 Docker Engine 的服务器；
- Git；
- 有效的环境变量配置（API Key、数据库密码等）。

首次部署大约 10–20 分钟，系统会自动完成数据库迁移、元数据导入和业务数据初始化。之后更新可以通过 `update.ps1` 一键完成。

---

### Q16： 基础版、中阶版、高阶版有什么区别？

**参考回答**：

| 版本 | 定位 | 面向用户 | 主要差异 |
|---|---|---|---|
| 基础版 | 业务问数版 | 业务人员、普通管理者 | 只开放智能分析工作台，后台预置配置 |
| 中阶版 | 客户管理员可配置版 | 数据负责人、IT 管理员 | 开放数据源、模型、数据集、报告模板维护 |
| 高阶版 | 生产运营版 | 超管、运营人员 | 开放权限、飞书同步、智能体配置、组织树 |
| 完整版 | 内部母版 | 研发、交付、定制客户 | 全量能力，持续迭代 |

我们建议先落地基础版，让业务人员用起来，验证问数闭环，再逐步开放中阶和高阶能力。

---

### Q17： 做一个数据集需要多久？

**参考回答**：

取决于数据准备的完整程度。如果业务表已经存在，只需要补充：
- 字段中文名和业务含义；
- 3–5 条 Golden SQL；
- 常见问题示例；
- 报告配置（层级字段、指标字段、风险阈值等）。

一个结构清晰的数据集，通常 1–2 天可以完成配置和测试。如果是全新的复杂业务口径，可能需要和业务部门一起梳理 3–5 天。

对于安吉尔这类组织层级复杂的企业，我们建议先做 1–2 个核心数据集，跑通后再批量扩展。

---

### Q18： 上线后怎么持续优化？

**参考回答**：

优化主要来自三个方向：

1. **补充 Golden SQL**：把用户常问的问题沉淀成标准 SQL，准确率会明显提升；
2. **完善字段字典**：业务别名、计算口径越清晰，Agent 理解越准；
3. **分析失败日志**：定期看哪些问题答错了、哪些路由偏了，针对性调整数据集画像和路由词。

中阶版和高阶版还会提供更完整的执行日志、健康检查、权限治理工具，帮助运营团队持续迭代。

## 五、演进与战略类

### Q19： 这个项目和市面上的 Text-to-SQL 产品有什么不同？

**参考回答**：

市面上很多 Text-to-SQL 产品只解决“把一句话转成 SQL”这件事，但企业级问数需要解决的是一整套问题：

- 该查哪个数据集？
- 口径怎么统一？
- SQL 生成后怎么保证安全？
- 结果怎么展示成业务人员能看懂的经营报告？
- 失败或歧义时怎么处理？

SmartAsk 不是只做 Text-to-SQL，而是做了一套“自然语言 → 数据集路由 → SQL 生成与复核 → 执行 → 报告输出 → 沉淀”的完整链路，并且在每一层都做了企业级控制和可解释设计。

---

### Q20： 长期演进方向是什么？

**参考回答**：

长期方向是从“回答是什么”升级到“解释为什么”和“建议怎么做”。

具体包括：
- 归因分析：为什么某个区域达成率低？
- 异常检测：哪些指标偏离了正常区间？
- 趋势洞察：基于历史数据预测未来走势；
- 行动建议：基于数据给出具体经营动作；
- 主动推送：从“被问才答”升级到“主动发现问题并推送”。

基础版就是这条演进路线的起点和稳定底座。

## 六、临场应变技巧

### 遇到不会回答的问题

- 不要硬编，可以说：“这个问题我需要回去和技术团队确认一下，会后给您准确答复。”
- 记录问题，展示专业态度。

### 遇到质疑准确率的问题

- 先承认基础版的定位：基础版先保证“不会乱答”，中阶版再提升“一次答对”。
- 用三层策略和确认机制作为证据。
- 补充：“我们在落地时会先用 20–30 个高频问题做验收，确保这些问题的准确率达标后再扩大范围。”

### 遇到要求现场演示的情况

- 提前准备 2–3 个稳定问题，不要临时发挥。
- 推荐演示问题：
  1. “商用事业部整体达成率是多少？”
  2. “哪个分公司完成最好？”
  3. “东部分公司下面哪些城市公司表现较好？”
- 如果现场网络或模型不稳定，宁可不演示，也不要冒险。

### 遇到和 BI 对比的问题

- 强调互补而不是替代。
- SmartAsk 解决的是“快速问一个具体问题”，BI 解决的是“长期监控和深度探索”。
- SmartAsk 的沉淀口径可以为 BI 提供更一致的数据基础。
