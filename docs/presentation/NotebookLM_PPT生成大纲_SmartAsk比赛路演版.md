# NotebookLM PPT 生成大纲：SmartAsk 智能问数项目（比赛路演版）

> 用途：复制到 NotebookLM / PPT 生成工具，生成一套 8-10 分钟比赛路演 PPT  
> 页数建议：12 页  
> 风格关键词：安吉尔品牌、纯净科技、企业级智能分析、克制高级、白底浅灰、红色点睛

---

## 全局视觉要求

请生成一套企业级 AI 数据产品路演 PPT，整体风格参考安吉尔品牌视觉：

- 主色：白色、浅灰、深灰黑。
- 点缀色：安吉尔品牌红 `#E61F24` 或 `#F51F19`，只用于关键数字、强调线、图标点睛、页码或小面积标签。
- 黑色不要用纯黑大面积压迫，使用高级深灰透明感，例如 `rgba(20,20,20,0.88)`、`#1F2937`、`#111827`。
- 背景：大面积白 / `#F8F9FA` / `#F3F4F6`，局部使用浅灰分区。
- 禁止高饱和渐变、霓虹光效、大面积红色背景、营销海报式夸张视觉。
- 卡片圆角控制在 8px 左右，边框用 `#E5E7EB`，阴影要轻。
- 图标风格：线性、极简、科技感；可使用数据库、聊天气泡、流程节点、盾牌、报告图表等图标。
- 图表风格：简洁仪表盘风格，红色只标记风险或关键结果，绿色仅表示成功/完成。
- 字体建议：中文使用思源黑体 / 阿里巴巴普惠体 / 苹方风格；标题稳重，正文清晰。
- 每页不要塞满文字，保留充足留白。

## P1 封面：项目名称与一句话价值

**页面标题**：SmartAsk 智能问数系统

**主文案**：
- 面向企业经营分析场景的自然语言问数工作台
- 让业务人员用一句话完成数据查询、口径确认、SQL 执行和经营分析报告生成

**画面设计**：
- 白色或浅灰背景。
- 中间放 SmartAsk 标题，右侧或底部放一条极细品牌红线。
- 可加入抽象的“问句 → 数据 → 报告”流程线。
- 左上角或右上角放小型 ANGEL 红色三角符号，不要大面积铺红。

**演讲提示**：
开场强调：这不是聊天机器人，而是企业经营分析的自然语言入口。

---

## P2 业务痛点：为什么经营问数难

**页面标题**：经营分析的三重困境

**核心内容**：
1. 响应慢：找表、找人、写 SQL、整理结果，数据不能及时服务决策。
2. 门槛高：业务人员懂问题，但不懂数据库、字段和 SQL。
3. 口径乱：同样的“达成率”“分公司”，在不同事业部可能代表不同统计口径。

**画面设计**：
- 三列卡片布局。
- 每列一个线性图标：时钟、代码/数据库、分叉口径。
- 每张卡只放一句核心描述。
- 红色只用于痛点编号或小图标，不要红底白字。

**演讲提示**：
举例：“哪些分公司达成率低于 30%”看似简单，但可能命中消费者事业部和商用事业部两个口径。

## P3 方案总览：一句话问数闭环

**页面标题**：从一句自然语言，到一份经营报告

**核心内容**：
- 用户自然语言提问
- 系统自动识别数据集与口径
- 自动生成并复核 SQL
- 查询结果结构化展示
- 输出经营分析报告

**画面设计**：
- 横向流程图：问题输入 → 口径识别 → SQL 生成 → 数据查询 → 报告输出。
- 每个节点用白色卡片，节点之间用细灰线连接。
- 当前重点节点用红色小圆点标记。

**演讲提示**：
强调 SmartAsk 是“自然语言入口 + 可解释数据链路 + 确定性报告输出”。

---

## P4 技术架构：前后端与数据底座

**页面标题**：项目架构：可部署、可追踪、可扩展

**核心内容**：
- 前端：Vue 3 + Element Plus + ECharts
- 后端：Flask + AskFlowController + 四 Agent 编排
- 数据：PostgreSQL 业务数据与元数据，Chroma 向量检索
- 部署：Docker Compose 三容器，frontend / backend / postgres

**画面设计**：
- 分层架构图：前端层、服务层、数据层、部署层。
- 用深灰线框表示模块，红色只用于核心引擎 AskFlowController。
- 右侧可以放“Docker Compose 一键部署”小标签。

**演讲提示**：
强调当前不是概念图，项目已经在 Docker 环境中跑通。

---

## P5 核心流程：四 Agent 协作

**页面标题**：四 Agent 协作，保证问数可靠

**核心内容**：
1. Agent1 路由：识别意图、匹配数据集、必要时确认口径。
2. Agent2 生成：根据字段、字典、规则和样例生成只读 SQL。
3. Agent3 复核：校验 SQL 安全、字段、层级、单位和口径。
4. Agent4 解读：基于结果生成经营分析结论。

**画面设计**：
- 四个步骤卡片横向排列。
- 每个 Agent 使用统一圆形图标。
- 当前系统亮点“前一环节不通过，后一环节不执行”放在底部提示条。

**演讲提示**：
强调不是直接让大模型写 SQL，而是工程化可控链路。

---

## P6 创新点：不是快答，而是答得准

**页面标题**：三项关键创新

**核心内容**：
1. 口径确认机制：不确定时主动确认，不乱答。
2. 规则 SQL + 大模型协同：高频问题稳定，新问题灵活。
3. ReportSpec 报告契约：结果结构可控、可测试、可复用。

**画面设计**：
- 三张重点卡片。
- 每张卡片顶部一个红色细线作为强调。
- 背景保持白色，卡片用浅灰边框。

**演讲提示**：
点明企业问数场景里，口径正确比“秒答”更重要。

**演讲提示**：

## P8 实测案例：从问题到正确结果

**页面标题**：真实问题验证：能问、能查、能解释

**核心内容**：
展示 3 个问题与结果：

1. 消费者事业部年度开单金额低于 3000 万的分公司  
   结果：京津、江浙沪、黑吉辽。
2. 商用事业部公共办公业务部剩余任务最多的人员  
   结果：王志军。
3. 电商事业部年度目标营收超过 1 亿的业务承接角色  
   结果：净水业务、京东直营、天猫直营。

**画面设计**：
- 左侧放“自然语言问题”气泡。
- 右侧放结果卡片，展示命中数量和关键结果。
- 中间用细箭头连接。

**演讲提示**：
突出系统能处理金额单位、组织层级、负责人和业务承接角色等复杂口径。

## P9 可信与安全：企业可用的前提

**页面标题**：可信可控，才适合企业经营分析

**核心内容**：
- 口径确认：多数据集歧义先确认。
- SQL 只读：禁止增删改。

- 执行追踪：前端展示流程，后端保留路由、SQL、复核和结果。

**画面设计**：
- 使用盾牌 + 流程节点图。
- 四个安全能力围绕中心“可信问数”。
- 红色用于风险拦截标记，绿色用于通过状态。

**演讲提示**：
强调企业 AI 应用不是炫技，而是要能解释、能排查、能被信任。
