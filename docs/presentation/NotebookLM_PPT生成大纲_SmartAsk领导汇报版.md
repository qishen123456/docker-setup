# NotebookLM PPT 生成大纲：SmartAsk 智能问数项目（领导汇报版）

> 用途：复制到 NotebookLM / PPT 生成工具，生成一套领导汇报 PPT  
> 页数建议：10 页  
> 风格关键词：安吉尔品牌、经营分析、稳重可信、少炫技、重进展和价值

---

## 全局视觉要求

请生成一套面向企业领导汇报的 PPT，风格克制、稳重、清晰，符合安吉尔品牌气质：

- 主背景使用白色和极浅灰 `#F8F9FA`，不要做深色大背景。
- 文字使用深灰黑 `#111827` / `#1F2937`，避免纯黑压迫。
- 品牌红 `#E61F24` / `#F51F19` 只做少量点缀：重点数字、进度线、强调标签、页脚细线。
- 页面整体要像企业经营分析报告，而不是营销海报。
- 图表简洁，优先使用 KPI 卡、流程图、里程碑、风险矩阵、三步计划。
- 不使用夸张渐变、霓虹光效、大面积红色块。
- 每页正文不要超过 5 行，适合领导快速浏览。
- 推荐版式：左侧结论，右侧证据；或上方一句结论，下方三到四个支撑点。

## P1 封面：项目阶段性汇报

**页面标题**：SmartAsk 智能问数项目阶段性汇报

**主文案**：
- 围绕经营分析场景，建设自然语言问数入口

**画面设计**：

## P2 为什么要做：经营分析中的实际问题

**页面标题**：当前经营问数仍存在效率与口径压力

**核心内容**：
1. 临时问题响应依赖人工，业务现场难以及时拿数。
2. 业务人员不会 SQL，查询依赖数据或 IT 同事。
3. 不同事业部、不同层级、不同字段口径容易混淆。
4. 高频问题重复取数，沉淀不足。

**画面设计**：
- 左侧一句结论：“经营问题越来越即时，数据响应仍偏人工。”
- 右侧四个问题卡片。
- 图标：人工流转、SQL、口径分叉、重复工作。

**汇报提示**：
不要过度讲技术，强调这是经营管理效率问题。

## P3 项目目标：先跑通基础闭环

**页面标题**：项目目标：让常规经营问题能够直接问、直接查、直接看

**核心内容**：
- 自然语言输入：业务人员按自己的话提问。
- 自动识别口径：判断数据集、组织层级、指标字段。
- 自动查询数据：生成并复核只读 SQL。
- 自动生成报告：输出结果卡片、表格和经营分析结论。

**画面设计**：
- 横向闭环图：提问 → 识别 → 查询 → 报告 → 沉淀。
- 每个节点使用浅灰卡片。
- 当前阶段标注“基础闭环已跑通”。

**汇报提示**：
明确 SmartAsk 不是替代 BI，而是经营分析的自然语言入口。

## P4 当前建设内容：系统能力全景

**页面标题**：当前已形成完整智能问数链路

**核心内容**：

- 数据：PostgreSQL 管理业务数据和元数据。

**画面设计**：
- 三层结构图：用户界面层、智能问数服务层、数据底座层。
- 中间突出“四 Agent 问数流程”。
- 右上角小标签：已完成基础链路。

**汇报提示**：
说明当前不是单点 demo，而是前后端和数据链路都已经打通。

## P6 当前验证结果：能跑、能查、能确认

**页面标题**：核心问数场景已通过验证

**核心内容**：

## P7 风险控制：不确定时先确认

**页面标题**：经营数据问答的核心原则：不确定时不乱答

**核心内容**：
1. 口径确认：多个数据集都可能回答时，先让用户选择。
2. SQL 只读：禁止写入、删除、修改。
3. SQL 复核：检查字段、层级、单位和口径。
4. 过程可追踪：保留路由、SQL、复核和结果信息。

**画面设计**：
- 中央放“可信问数”。
- 四周放四个风险控制模块。
- 适度使用盾牌、勾选、数据库锁图标。

**汇报提示**：
这页是给领导吃定心丸：项目不是只追求快，而是优先保证可信和可控。

## P8 项目价值：对业务和数据团队的收益

**页面标题**：项目价值：提升效率、统一口径、沉淀能力

**核心内容**：
- 对业务人员：不用写 SQL，直接提问拿结果。
- 对经营管理：常规问题响应更快，现场复盘更高效。
- 对数据团队：减少重复取数，把精力转向治理和专题分析。
- 对公司：沉淀统一指标口径和经营分析能力。

**画面设计**：
- 四象限价值矩阵。
- 每个象限一句短结论。
- 使用浅灰背景、白色卡片、红色关键词。

**汇报提示**：
强调 SmartAsk 是效率工具，也是数据口径沉淀工具。

## P10 下一步计划：从能用到好用

**页面标题**：下一步计划：扩大试用、沉淀问法、完善治理

**核心内容**：
