# 基础版智能问数演讲稿（10 分钟专业版）

> 配套 PPT：《基础版智能问数 PPT 大纲.md》（专业版 21 页）  
> 演讲时长：约 10 分钟  
> 建议语速：每分钟 220–240 字

---

## P1 封面（20 秒）

各位领导、各位同事，大家好。今天我来介绍 SmartAsk 智能问数系统基础版。

我们的目标不是做一个聊天机器人，也不是替代 BI，而是在企业经营分析场景下，构建一个“自然语言入口 + 可解释数据链路 + 确定性报告输出”的 Autonomous BI 最小闭环。

---

## P2–P3 定位与痛点（1 分钟）

传统经营分析有三个典型困境：响应慢、门槛高、口径乱。

一个业务总监会后问一句“上周达成率多少”，往往要经历找表、找人、写 SQL、对口径、整理表格这一长串过程。SmartAsk 基础版要做的，就是把这一过程压缩成一句话：用户开口问，系统直接给出数据和分析结论。

但基础版不是追求大而全，而是先聚焦一件事——让一句自然语言问题，稳定地变成一份可解释的经营报告。

---

## P4–P6 三个核心设计原则（2 分钟）

围绕这个目标，我们定了三个设计原则。

第一，先跑通最小闭环。问题能理解、数据集能锁定、SQL 能生成并执行、报告能输出并沉淀，这个闭环先稳住，再谈其他。

第二，基础流程稳定、进阶流程增强。我们用一个 AskFlowController 来决策本轮问题走基础流程还是进阶流程。基础流程是稳定的四 Agent 引擎，服务 80% 的常规问题；进阶流程通过 Skill 和工具链路处理更复杂的分析需求。两套流程最终输出统一的结果契约，前端无感知。进阶异常时还能自动回退到基础流程。

第三，三层解耦。底层是数据集知识层，包括 DDL、数据字典、LLD、Golden SQL、Agent Prompt，回答“AI 是否懂这个数据集”。中间是报告契约层，定义指标、层级、阈值、信号灯、标准输出列，回答“SQL 结果如何变成报告”。上层是场景渲染层，根据问题动态识别 detail、comparative、ranking、diagnostic 等展示方式，回答“这个问题该用哪种界面”。

---

## P7–P11 架构与四 Agent（2.5 分钟）

整体架构上，前端是 Vue 3 + Element Plus + ECharts，后端是 Flask，核心模块包括 smart_chat 接口、AskFlowController、四 Agent 编排、ReportSpec v2 构建、报告契约配置和多数据源路由。数据层使用 PostgreSQL 存储元数据和业务数据，Chroma 做向量检索。整套环境通过 Docker Compose 一键部署。

四 Agent 协作是系统的核心。Agent1 负责意图识别和数据集路由，它不只是在“选表”，而是综合数据集名称、别名、业务域、组织树、画像、历史上下文和 Golden SQL 相似度做综合评分。如果路由不确定，系统会返回确认卡片，由用户确认口径，而不是强行给出一个可能错误的答案。

Agent2 负责 SQL 生成。这里不是每次都依赖大模型“蒙”SQL，而是有三层策略：高匹配问题走 Golden SQL 直执行，高频模式走规则 SQL 兜底，新问题才由 Agent2 动态生成。

Agent3 负责 SQL 复核，检查是否只读、字段是否存在、JSONB 读取是否合理、聚合口径是否正确。复核通过后才会执行。如果执行失败，系统会进入 Agent2Repair 自动修复闭环：捕获数据库真实错误，基于 failed_sql、error 和 DDL 生成修复 SQL，再经过复核和执行。仍然失败则优雅降级，保留诊断信息。

Agent4 负责业务解读，基于 SQL 结果生成经营分析结论和建议。

---

## P12–P14 报告契约与前端设计（1.5 分钟）

报告输出是我们非常重视的环节。我们不让大模型自由生成 HTML，而是由后端输出一个确定性报告协议 ReportSpec v2。

报告契约定义了每个数据集的标准输出列、指标、层级、风险阈值和信号灯规则。`report_spec_builder` 根据契约和问题场景动态生成 report_spec，包括 analysisMode、layoutTemplate、KPI、图表、下钻结构，以及 provenance 可追溯信息。前端按 report_spec 渲染，保证报告结构稳定、可解释、可复现。

前端设计上，我们参考火山引擎 DataAgent 的体验：中间区回答用户真正关心的问题，展示执行计划、关键进展、结果摘要和报告卡片；右侧区展示完整执行详情，包括 Skill 轨迹、路由分数、SQL、表格预览和自检提示。核心原则是：中间区不变成日志区，右侧区不变成第二份答案。

---

## P15–P18 安全、部署与验证（1.5 分钟）

安全方面，基础版做了五层设计。数据集访问权限过滤掉未授权数据集；组织提及权限检查拦截未授权组织；行级权限过滤在 SQL 外层自动包一层组织范围 WHERE；SQL 只读执行禁止任何增删改操作；异常自动修复降低因字段或语法问题导致的失败。

行级权限落地根据数据现状有三种方式：源表直接有组织编码的最简单；只有名称的作为过渡方案；关系复杂的通过新增业务组织映射表处理，这也是我们最推荐的长期方案。

部署上，基础版采用 Docker Compose 三容器方案：PostgreSQL、Flask 后端、nginx 前端。首次启动会自动完成数据库迁移、元数据导入和业务数据快照导入，用户访问 localhost:8888 即可使用。交付时后台配置由交付方预置，业务用户登录后只看见“智能分析工作台”。

当前状态上，前端构建、后端语法检查、健康检查均已通过，四类报告场景识别测试全部通过，报告契约健康度达到 100/100，基础问数链路已经稳定可用。

## P19–P21 价值与演进（1 分钟）

基础版的价值可以总结为五点：降低门槛，业务人员不用写 SQL；缩短响应，常规问题从小时级压缩到分钟级；沉淀口径，通过 Golden SQL 和复核机制减少口径不一致；可信可解释，路由分数、执行轨迹、复核说明和报告契约都可追溯；建立底座，为进阶流程、权限治理和平台化运营奠定基础。

后续演进路线也很清晰：V2 中阶版重点解决准确率和可控性；V3 高阶版解决可治理、可配置、可运维；V4 终极版走向主动分析和经营智能体。基础版不是终点，而是这条演进路线的稳定底座。

SmartAsk 基础版，让每一个人都能开口问数。谢谢大家，欢迎提问。
