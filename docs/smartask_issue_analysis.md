# SmartAsk 端到端测试问题根因分析与完整解决方案

> 分析对象：`config/smartask_test_results_20260627_070408.json`（170 题全量重测）  
> 异常/待确认题数：82 题  
> 当前阶段：只分析原因、给出方案，**不修改代码**

---

## 一、总体结论

本次 170 题测试中，约 **52% 的题目无明显异常**，剩余 82 题的异常可归纳为 **8 大类根因**。其中数量最多的是**卡片标题被系统模板化改写**（43 题），属于体验问题；真正会导致答案错误 or 无法回答的核心技术问题集中在：

1. **通用层级词被当作具体节点** → SQL 过滤条件错误（代表处/分公司/业务部等）
2. **路由确认策略偏保守/偏激进** → 该确认的没确认，不该确认的弹出确认
3. **层级下钻的父子映射不稳定** → 下属节点查不出
4. **排序指标、多条件筛选、跨数据集对比、毛利率等指标口径** 未正确解析

下面按影响面和优先级逐类分析。

---

## 二、问题分类、根因与解决方案

### 类型 A：通用层级词被误当作节点实体（核心 BUG）

**典型问题**

- `I4` 后 5 的代表处 → 返回 0 行
- `I13` 哪个分公司最低 → 返回 0 行并弹确认
- `R4` 分公司业绩排名 → 返回 0 行
- `R16` 业务部业绩、`R20` 代表处业绩 → 数据集锁定后为空

**根因分析**

Agent1/Agent2 在解析时，把「代表处」「分公司」「业务部」这种**层级标签**和具体节点名称（如「东部分公司」「甘青宁代表处」）混在一起，作为 `resolved_entities` 传给 SQL 生成器。

生成的 SQL 里多了类似：

```sql
WHERE 层级 = '代表处' AND 节点名称 IN ('代表处')
```

而真实数据里没有任何节点真的叫「代表处」，因此结果为空。

> 注：`I4 后 5 的代表处` 已单独验证并修复，修复方式见下；但同类问题在分公司/业务部/城市分公司等层级仍存在。

**解决方案**

1. 在 SQL 生成入口维护一份 denylist：
   ```python
   LEVEL_LABELS = {"事业部", "分公司", "代表处", "业务部", "业务代表", "城市分公司", "承接人"}
   ```
2. 从 `resolved_entities`、正则提取、组织树解析得到的「实体」中，**纯层级标签且不包含具体前缀的**，不允许进入 `节点名称 IN (...)` / `上级名称 IN (...)` 过滤。
3. 只对具体节点名（如「东部分公司」「甘青宁代表处」）生成节点过滤。
4. 涉及文件：
   - `backend/four_agent_ask.py`（代表处/分公司/业务代表/业务部排名与筛选分支）
   - `backend/smartask_advanced/skills/planner.py` 或 SQL builder（advanced 流程）

### 类型 B：路由确认策略错误（该确认的没确认 / 不该确认的确认了）

**典型问题**

- `R12` 事业部的达成率 → 应确认，直接锁定数据集 2
- `R16` 业务部业绩 → 应确认，直接锁定数据集 3
- `R20` 代表处业绩 → 应确认，直接锁定数据集 3
- `E1` 华北分公司的业绩 → 节点不存在，反而返回空结果
- `E4` 达成率低于 0% 的分公司 → 意外弹确认
- `E5` 2023 年业绩 → 时间不支持，未给明确提示

**根因分析**

1. `route_guard.py` 的 `exact_match_texts` 只看数据集名称/业务域/同义词命中，没识别问题里是否只包含通用集合词。
2. `DatasetRouteSkill.score` 对「事业部/分公司/业务部/代表处」等通用层级词没有显式剔除，导致某个数据集因其他特征（如业务域、同义词）得分偏高而 auto_lock。
3. 对「不存在节点」「不支持时间」「非法 topN」等边界语义缺少前置校验，fallback 为确认或 0 行。

**解决方案**

1. **强制确认规则**：如果问题只包含 `LEVEL_LABELS` 中的通用层级词，且未命中任何具体节点名，则强制 `requires_confirmation`，不让 route_guard auto_lock。
2. **从评分中剔除通用层级词**：`DatasetRouteSkill._alias_score` 和 token overlap 不应给「事业部」「分公司」等词加分。
3. **节点存在性校验**：Agent1 解析出节点名后，先在组织树/数据字典里校验是否存在；不存在直接返回：「未找到名为“华北分公司”的节点，请检查名称或切换数据源」。
4. **时间维度拦截**：问题含年份/季度而数据集只有当前年时，返回明确提示：「当前数据集仅支持 2026 年」。
5. **非法数量校验**：topN ≤ 0 或超大时，自动修正为 10 并提示用户。
6. 涉及文件：
   - `backend/smartask_advanced/skills/route_guard.py`
   - `backend/smartask_advanced/skills/dataset_route.py`
   - `backend/four_agent_ask.py` 中的 `_route_entity_resolution` 与边界校验

### 类型 C：层级下钻父子映射错误

**典型问题**

- `L1` 商用事业部东部分公司下有哪些代表处
- `L14` 商用事业部西部分公司代表处业绩
- `L19` 商用事业部餐饮业务部代表处业绩
- `I12` 商用事业部南部分公司下属代表处业绩
- `X5` 商用事业部东部分公司和南部分公司代表处业绩对比

**根因分析**

不同数据集的层级字段不一致：
- 数据集 3（商用）：分公司 → 代表处 → 业务代表
- 数据集 62（电商）：业务部 → 细分业务 → 承接人
- 数据集 2（消费者）：事业部 → 分公司 → 城市分公司

SQL 生成器用统一的 `上级名称` 字符串匹配来做下钻。当问题中的父节点名和数据集实际层级字段不匹配（如「东部分公司」对应不上 `上级名称`），或同一父节点在不同层级出现（如「餐饮」既可以是业务部也可以是代表处），就会查空。

**解决方案**

1. **每个数据集配置层级映射**：在 dataset profile / report_config 里声明层级字段和父子关系，例如：
   ```json
   {
     "hierarchy": [
       {"level": "事业部", "field": "事业部"},
       {"level": "分公司", "field": "分公司", "parent": "事业部"},
       {"level": "代表处", "field": "代表处", "parent": "分公司"},
       {"level": "业务代表", "field": "业务代表", "parent": "代表处"}
     ]
   }
   ```
2. **下钻 SQL 使用递归或路径匹配**：
   - 生成 `组织路径 LIKE '商用事业部/东部分公司%'` 或递归 CTE，而不是仅依赖 `上级名称`。
   - 对多父节点情况，先用存在性校验确定父节点真实层级。
3. **存在性校验前置**：下钻前先确认父节点存在，不存在直接提示。
4. 涉及文件：
   - `backend/dataset_report_config.py`
   - `backend/four_agent_ask.py` 下钻相关分支
   - 数据集元数据配置

### 类型 D：排序指标识别失败

**典型问题**

- `I10` 所有细分业务按年度开单金额排名
- `X16` 消费者事业部业绩排名，按年度开单金额排
- `X17` 商用事业部代表处排名，按达成率排

**根因分析**

Agent2 解析 `sort_metric_column` 失败，fallback 到默认指标（通常是达成率）。问题里「按年度开单金额排」被忽略或识别为筛选条件。

**解决方案**

1. NLU 增强排序指标识别：支持「按 X 排 / 按 X 排序 / X 最高的 N 个 / 按 X 从低到高」。
2. Agent2 把排序指标明确传给 SQL builder，覆盖默认指标。
3. 当排序指标与问题中的其他指标冲突时，优先使用问题明确指定的指标。
4. 涉及文件：
   - `backend/smartask_advanced/skills/planner.py`
   - `backend/four_agent_ask.py` 排名相关分支

---

### 类型 E：多条件筛选只保留一个条件

**典型问题**

- `X7` 消费者事业部哪些分公司达成率低于 50% 且缺口超过 1000 万
- `X8` 商用事业部达成率高于 80% 且开单金额超过 5000 万的代表处

**根因分析**

Agent2 的条件解析只支持单条件，多个条件被截断或只取第一个。

**解决方案**

1. 在 Agent2 里把过滤条件解析成列表（每个条件含字段、比较符、值）。
2. SQL builder 将每个条件独立生成 `WHERE` 片段后用 `AND` 拼接。
3. Agent3 SQL 复核增加多条件校验：检查 SQL 中过滤条件数量是否和问题一致。
4. 涉及文件：
   - `backend/smartask_advanced/skills/planner.py`
   - `backend/smartask_advanced/skills/sql_review.py`
   - `backend/four_agent_ask.py`

### 类型 F：指标口径错误 / 数据集 62 指标未映射

**典型问题**

- `I30` 电商事业部毛利率最高的业务部 → 用了达成率
- `M21` 电商事业部哪个业务线利润最高 → 用了达成率
- `C16` 电商事业部毛利率最高的 3 个业务 → 用了达成率
- `M4` 电商事业部年度目标营收 vs 年度开单金额对比 → 空结果
- `L4` 电商事业部净水业务负责人是谁 → 空结果

**根因分析**

数据集 62 的字段与消费者/商用不同（毛利率、利润、年度目标营收、承接人、细分业务），但 SQL 生成器只认识达成率/年度开单金额/总任务金额/剩余任务金额。

**解决方案**

1. **数据字典补全**：为数据集 62 补充指标定义和同义词：
   - 毛利率 / 利润
   - 年度目标营收完成率
   - 承接人 / 负责人
2. **SQL 生成器读取数据字典**：按需生成 `ROUND(毛利/收入, 2)` 或读取已有字段。
3. **明细查询分支**：「负责人是谁」「承接人是谁」走明细查询，直接返回负责人字段，不做聚合。
4. **双指标对比**：`vs / 对比` 类问题支持同时 SELECT 两个指标，用表格/条形图对比展示。
5. 涉及文件：
   - `backend/dataset_report_config.py`
   - `backend/four_agent_ask.py` 指标映射与 SQL builder
   - `backend/smartask_advanced/skills/planner.py`

### 类型 G：跨数据集对比未识别

**典型问题**

- `R8` 商用事业部和消费者事业部的总任务金额对比

**根因分析**

当前路由和执行链路是单数据集模式。Agent1 只返回一个最高分数据集，Agent2 也按单数据集生成 SQL，没有跨数据集执行/合并阶段。

**解决方案**

1. **短期**：检测到多个明确数据集名称/业务域时，直接提示用户：「当前暂不支持跨数据集对比，请分别提问」。
2. **中期**：在 Agent2 增加「跨数据集对比」意图分支：
   - 把问题拆成多个子查询；
   - 对每个数据集分别生成 SQL；
   - 按相同指标对齐结果；
   - 报告层用对比卡展示多个数据集 KPI。
3. **长期**：如果指标口径不一致（金额单位、字段含义不同），系统应显式提示，而不是强行对比。
4. 涉及文件：
   - `backend/smartask_advanced/skills/route_guard.py`
   - `backend/smartask_advanced/skills/planner.py`
   - `backend/four_agent_ask.py`
   - 前端对比卡组件

### 类型 H：报告卡片标题模板化 / 与问题不符

**典型问题**

- `I28` 消费者事业部缺口最大的分公司 → 标题变成「达成率排名前3的分公司」
- `I29` 商用事业部剩余任务最少的分公司 → 标题变成「达成率排名后10的分公司」
- `I1` 消费者事业部哪个分公司完成率最高 → 标题含「达成率排名前3的消费者事业部」
- 大量排名/筛选题标题被系统改写，导致测试脚本触发「标题与问题关联度低」

**根因分析**

Agent4 / `report_spec_builder` 为了套用固定模板，把：
- 「哪个最低」→ 改成「达成率排名前3的...」
- 「业绩排名」→ 改成「达成率排名前3的...」

标题失去了原问题中的关键意图词（最低、缺口最大、低于 X%）。

**解决方案**

1. **意图感知的标题模板**：
   - 极值：「达成率最低的分公司」「缺口最大的分公司」
   - 筛选：「达成率低于 10% 的城市分公司」
   - 排名：「达成率排名前 5 的代表处」
   - 下钻：「东部分公司下属代表处业绩」
   - 对比：「东部分公司与南部分公司对比」
2. **优先复用问题原句关键词**：如果问题本身不含「排名」词，标题不要强行加「排名前N」。
3. **兜底标题**：无法生成贴切标题时，使用「问题原文 + 数据集名称」。
4. 涉及文件：
   - `backend/report_spec_builder.py`
   - `backend/smartask_advanced/skills/conclusion_advice.py`
   - 前端 `ResultDigestCard.vue` 标题渲染

## 三、实施优先级与建议顺序

| 优先级 | 修复项 | 预期收益 | 涉及范围 |
|---|---|---|---|
| P0 | 通用层级词过滤（类型 A） | 解决大量「前/后 N 排名」空结果 | SQL 生成器 |
| P0 | 路由确认策略（类型 B） | 解决该确认没确认、不该确认却确认 | route_guard / dataset_route |
| P1 | 层级下钻父子映射（类型 C） | 解决下属/下钻类空结果 | dataset profile + SQL builder |
| P1 | 排序指标识别（类型 D） | 解决「按 X 排」类问题 | NLU / planner |
| P1 | 指标口径补全（类型 F） | 解决数据集 62 毛利率/利润/负责人 | 数据字典 + SQL builder |
| P2 | 多条件筛选（类型 E） | 支持复合过滤 | planner + sql_review |
| P2 | 边界语义兜底（类型 B 子项） | 提升体验 | Agent1/Agent2 入口校验 |
| P3 | 跨数据集对比（类型 G） | 新功能，可短期拦截 | route + planner |
| P3 | 报告标题优化（类型 H） | 提升卡片可读性 | report_spec_builder + 前端 |

## 四、推荐的一轮修复流程

1. **统一 `LEVEL_LABELS`**：在后端定义一份全局层级标签集合，供 `dataset_route`、`route_guard`、`four_agent_ask`、planner 共同使用。
2. **修改 `route_guard.py`**：
   - 只含层级词 → 强制确认；
   - 不存在节点 → 直接提示；
   - 跨数据集 → 提示或进入跨数据集分支。
3. **修改 `four_agent_ask.py` 的排名/筛选/下钻分支**：
   - 过滤掉 `LEVEL_LABELS` 中的纯层级词；
   - 下钻使用层级映射配置 + 路径匹配。
4. **补全数据集 62 指标映射**：毛利率、利润、目标营收完成率、承接人。
5. **增强 Agent2 意图解析**：排序指标、多条件、明细查询（负责人是谁）。
6. **优化 Agent4 标题**：按意图选择模板，减少模板化扩展。
7. **更新测试脚本**：标题匹配启发式放宽，减少误报；对修复后的题目重新跑批量测试。
