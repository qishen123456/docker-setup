# 三视角数据分析方法论 - SmartAsk 集成设计

> **性质**：设计文档，不修改任何代码。
> **目的**：把花叔团队三视角方法论与 SmartAsk 四智能体流水线的对应关系固化下来，标注未来集成切入点。
> **前置文档**：`data-analysis-methodology.md`（方法论本身）

---

## 一、SmartAsk 四智能体流水线现状

### 1.1 流水线结构

```
用户提问
  ↓
Agent1（语义路由 / 数据集识别 / 歧义判断 / 确认决策）
  ↓
Agent1.5（组织主体解析 / 层级归属 / 集合表达拆解）
  ↓
Agent2（SQL 生成，含规则 SQL / Golden SQL / LLM 生成三路）
  ↓
Agent3（SQL 审计 / 字段校验 / 安全复核）
  ↓
执行查询（返回 rows + columns + row_count）
  ↓
Agent4（业务分析官 → 生成"老板视角的经营分析结论"）
  ↓
返回用户
```

### 1.2 Agent4 现状分析

**位置**：`backend/four_agent_ask.py` 第 7760-7833 行

**当前能力**：
- 接收查询结果（rows/columns）+ Agent3 复核结果 + LLD 背景 + 报告配置
- 生成一段 Markdown 格式的经营分析报告
- 有一个规则兜底路径 `_build_fallback_analysis`（第 506 行）
- 有一个分层管理报告生成器 `_build_layered_management_report`（第 619 行），能做层级分布和达成率对比
- 有全局报告标准（第 7775 行），规定了格式化、问题优先、模板优先等规则

**当前不足**（对照三视角方法论）：

| 三视角方法论 | Agent4 现状 |
|---|---|
| 趋势分析（拐点/季节性/同比环比） | ❌ 无系统化趋势分析，不识别拐点和季节性 |
| 结构分析（占比/帕累托/集中度） | ⚠️ 有部分层级分布，但无占比分解、帕累托、集中度风险 |
| 异常分析（3σ/IQR/突变/数据质量） | ❌ 完全无异常检测能力 |
| 多视角合成 | ❌ 直接生成单段文本，无多视角交叉印证 |

## 二、集成切入点设计

### 2.1 三个可选方案

#### 方案 A：增强 Agent4（推荐 - 最小侵入）

```
Agent3 审核通过 → 执行查询 → 查询结果
                                    ↓
                         ┌──────────┼──────────┐
                         ↓          ↓          ↓
                    趋势分析    结构分析    异常分析
                    (prompt)    (prompt)    (prompt)
                         └──────────┼──────────┘
                                    ↓
                          Agent4 合成层
                    （三视角交叉印证 + 报告生成）
```

**改动范围**：
- `four_agent_ask.py` 中 Agent4 调用部分（第 7770-7833 行）
- 新增 3 个分析 prompt 文件（放在 `config/` 下）
- Agent4 的 system_prompt 增加三视角合成指令

**优点**：不动流水线结构，只增强最后一环
**缺点**：三视角串行执行会增加延迟（可通过并行 LLM 调用缓解）

#### 方案 B：独立后分析层

```
查询结果 → Agent4（保持不变）→ 现有报告
                ↓
          后分析层（三视角并行）
                ↓
          增强报告（现有报告 + 三视角补充）
```

**改动范围**：
- 在 `ask_flow/` 或新建 `post_analysis/` 模块
- 路由层增加后分析触发条件

**优点**：完全不影响现有流水线，可开关
**缺点**：两份报告可能重复或矛盾

#### 方案 C：配置化分析模板

不增加 LLM 调用，把三视角方法论转化为规则模板：
- 趋势：用 SQL 窗口函数做同比/环比/滑动平均
- 结构：用 SQL GROUP BY + 占比计算
- 异常：用 SQL 统计函数（STDDEV/PERCENTILE）做离群标记

**改动范围**：
- `config/` 下新增分析模板配置
- Agent2 增加分析型 SQL 生成能力

**优点**：零额外 LLM 调用，延迟最低
**缺点**：灵活性差，无法做拐点解释和风险分级

### 2.2 推荐路径

**短期**：方案 C（配置化模板），在 Agent2/Agent3 层面增加分析型 SQL 能力，零 LLM 开销。

**中期**：方案 A（增强 Agent4），引入三视角 prompt 并行调用 LLM，在 Agent4 合成。

**长期**：方案 B（独立后分析层），作为可插拔模块，按数据集策略开启。

## 三、与现有配置体系的对接

SmartAsk 已有的配置体系完全可以承载三视角方法论：

| 配置文件 | 现有用途 | 三视角对接方式 |
|---|---|---|
| `config/datasetPolicies.json` | 数据集策略 | 新增 `analysis_modes` 字段，按数据集启用趋势/结构/异常 |
| `config/feature_flag.json` | 功能开关 | 新增 `three_perspective_analysis` 开关 |
| `config/advancedRoles.json` | 角色权限 | 控制谁能触发深度分析 |
| `config/` 下 agent prompts | Agent1-4 的 prompt | 新增 Agent4 的三视角增强 prompt 片段 |
