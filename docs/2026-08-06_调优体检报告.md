## 4. 运行时风险（已生效，非"未来可能"）

### R1：生产运行 Flask 内置开发服务器

实证——容器内进程：

```
/usr/local/bin/python /app/backend/app.py
```

链路：`Dockerfile:45 CMD ["python", "bootstrap.py"]` → bootstrap 经 `os.execv` 交棒 → `app.py:255 app.run(host="0.0.0.0", port=BACKEND_PORT, debug=False, use_reloader=False)`

容器内 `gunicorn` / `waitress` / `uwsgi` / `gevent` **均未安装**。

**耦合陷阱**：正因单进程，`self._pending_confirmations`（`four_agent_ask.py:55`）才能工作。若单独引入 gunicorn 多 worker，确认会话立即串号/丢失。**R1 与会话态外置必须同批改造。**

### R2：SSE 每请求裸起线程 + 无界队列

```
smart_chat.py:705   event_queue = queue.Queue()                          无 maxsize
smart_chat.py:769   threading.Thread(target=run_ask, daemon=True).start()
smart_chat.py:981   event_queue = queue.Queue()                          无 maxsize
smart_chat.py:1042  threading.Thread(target=run_confirm, daemon=True).start()
```

无线程池、无并发上限、无取消机制、无超时。

**新增发现（前序未报）**：

```
feishu_sync.py:214  threading.Thread(target=sync_worker)   ← 缺 daemon=True
feishu_sync.py:267  threading.Thread(target=sync_worker)   ← 缺 daemon=True
```

非守护线程阻止进程优雅退出，容器 stop 时须等超时被 SIGKILL。

### R3：会话态无锁

`_pending_confirmations` 读写点：`four_agent_ask.py:7837`（遍历判过期）/ `7839`（pop）/ `7849`（写）/ `8878`（读）/ `9058`（pop）。

全仓搜不到 `threading.Lock` / `RLock`。SSE 裸线程并发读写同一无锁 dict，L7837→L7839 存在 TOCTOU 窗口。单进程低并发下不易触发，但属真实缺陷。
