## Phase P1-a：影子模式（2 周，主力阶段）

**范围冻结（门禁 6.3 节 3 条，不扩）**：
1. 统一候选出口校验（书架否决权落到所有候选出口）
2. 首字母静默护栏（禁静默映射直答，必须 soft_hint/clarify）
3. 方向词表补齐 + 级联修错字（好↔不好/高↔低/多↔少/差↔好）

**实现要点**（设计文档 §4 已定，此处为执行约束）：
- 独立 GatekeeperLLMClient（锁快模型、timeout 3~5s、零重试、禁共享 `_preferred_model_id` 单例）——照搬 `shadow_gatekeeper.py:296-302` 模式
- 挂载点：`ask():9341` 后、Agent1 前；与现有规则层**并行只记录**，fail-open（异常/超时/未命中 → 静默放行，兜底=问数流水线本体）
- 影子日志 schema：question / 规则层 verdict / LLM verdict / confidence / latency_ms / 校准标签（人工抽检）
- 书架证据按 `allowed_dataset_ids` 裁剪（权限红线）

**量化门槛（评审修订版，替代旧"误拦率<2%"单指标）**：

- **一致率拆双层**（单指标 95% 不可行——现状 36% 里混着规则层候选文案抖动，无法归因）：
  - **verdict 级一致率**：硬题（`deterministic=true`）要求 3/3 恒定；软题允许多数决，目标 ≥85~93%
  - **候选文案级一致率**：按集合相似度单独计量，只做观察不做门禁
- **真误拦 <2%**（"误拦"=候选错误/不该拦而拦；`reasonable_clarify` 标签豁免合理澄清）
- **澄清率指标修正**（原计划 37.4%→≤15% 自相矛盾：37.4% 基线从未拆账，且首字母护栏上线短期必然**推高**澄清率）→ 改为「**不合理澄清率 ≤5%**（候选错误/规则误触发部分）+ 总澄清率降为观察指标」
- 高置信桶准确率 ≥95%，ECE ≤0.1
- 样本 ≥200（按实测流量 ~17 条/天，2 周可达；不承诺 500）

**可观测性补项（评审遗漏风险）**：
- Gatekeeper 串行段设 **P95 延迟门槛**（建议 ≤500ms 影子期实测校准；timeout 3~5s 是熔断不是常态）
- fail-open 放行时若**规则层与 LLM 结果冲突，仲裁权归属**写死：影子期以规则层为准（现状），P1-b 开放后按四态置信度分流表仲裁——不预设"谁赢"，按置信度桶数据说话

## Phase P1-b：拦截开放（达门槛后）

- 四态分流（pass/rewrite/soft_hint/clarify）按门槛逐步开放：先 soft_hint（非阻断），后 clarify（阻断）
- 规则层退役顺序：direction_ambiguity → typo_fastpath → 守门员纠正条，每步以影子对照数据为前置
- 回滚：feature_flag 一键关闭，恢复现行规则层

## 验收口径（不可妥协）

1. **一切验收走 HTTP 真实链路** `/api/smart-chat`（svc 直调假象已三方正验）
2. 一切"失败模式"声明须 **≥3 次复跑**（本轮教训：单次复验误判 4 条）
3. 验收用例 = fixtures 入仓基线（争议 14 题×3 + 负样本 54 + 教科书题 3 跑 + 探测 5 题）+ 标签化判定，**机器执行，不靠人肉**

## 风险登记

| 风险 | 缓解 |
|---|---|
| LLM 非确定性导致门槛永远达不到 | 门槛含一致率指标本身就量化它；影子期可先调 temperature/prompt 再判 |
| 拼音索引接入主链路的行为变化混入 P1 归因 | 拼音索引接入属于 P1 范围第 2、3 条的实现手段，接入前后各跑一轮基线对照 |
| 并发压测互相干扰（多 AI 同时跑） | runner 串行为默认；token 固化（Phase -1 #4）；压测时间窗约定 |
| 拆出项被遗忘 | backlog 文件入仓 + 本计划引用 |
