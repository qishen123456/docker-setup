# 三视角数据分析方法论

> **来源**：从花叔数据分析专家团（huashu-data-pro）的 4 份专家 prompt 中提炼。
> **性质**：框架无关的分析规则文档，不依赖任何平台运行时（TeamCreate/Agent/SendMessage 等）。
> **用途**：任何 LLM、任何后端代码均可将本文档作为分析指令使用。特别地，本文档标注了与 SmartAsk Agent4 的对应关系（见同目录 `data-analysis-integration-design.md`），未来增强 Agent4 分析能力时可直接引用。

---

## 一、核心理念

> **三个视角同时看一份数据，永远比一个视角反复看好。**

数据分析的难点不在于"看到一个数"，而在于"看到一个数之后能不能从多个视角同时解读"。三种视角各自独立、互不干扰，最后由合成层交叉印证：

| 视角 | 回答的问题 | 不回答的问题 |
|---|---|---|
| 趋势 | 这些数字随时间怎么变化 | 数字内部怎么组成的、哪里出问题了 |
| 结构 | 这些数字内部是怎么组成的 | 时间怎么变的、哪里出问题了 |
| 异常 | 哪里偏离了常态 | 时间怎么变的、内部怎么组成的 |

**边界原则**：每个视角只守自己的领域，域内全包，域外不越界。跨视角的交叉印证由合成层负责。

## 二、趋势分析规则

### 2.1 适用场景

数据中存在时间字段（日/周/月/季/年），且需要理解"正在变好还是变坏"、"变化是季节性还是结构性"。

### 2.2 分析步骤

1. **识别时间字段** -- 确认哪一列是时间，颗粒度是日/周/月还是其他
2. **识别度量字段** -- 确认要分析哪些指标（由上层指定或自动检测数值列）
3. **基础描述统计** -- 计算 min/max/mean/median/数据起止时间范围
4. **趋势类型判定** -- 判定为以下之一：
   - 上升：连续或总体上升
   - 下降：连续或总体下降
   - 平稳：波动在正常范围内
   - 周期波动：有规律的反复
5. **拐点检测** -- 找出增长曲线明显改变方向的时间点（slope change point），至少 1 个、最多 3 个最重要的
6. **季节性识别** -- 检查周/月/季/年的周期性规律
7. **同比/环比计算** -- 对比基期数据，算出变化幅度
8. **滑动平均与平滑** -- 剥离短期噪声，看清长期信号（可选）
9. **保守趋势预测** -- 基于历史规律给短期外推，必须标注置信区间

### 2.3 输出结构

```json
{
  "perspective": "trend",
  "summary": "一句话整体趋势判断",
  "metrics_analyzed": ["指标1", "指标2"],
  "time_range": "2026-01 to 2026-04",
  "findings": [
    {
      "metric": "指标名",
      "trend_type": "上升|下降|平稳|波动",
      "magnitude": "+23.5% YoY",
      "key_inflection": {
        "date": "2026-03-15",
        "description": "单周下跌 18%，疑似与 X 事件相关"
      },
      "seasonality": "月度周期，每月中旬偏低",
      "confidence": "高|中|低"
    }
  ],
  "chart_recommendations": [
    "建议放一张 2026 Q1 营收月度走势线图"
  ]
}
```

### 2.4 降级条件

- 少于 3 个时间点：无法做趋势判断，标注"数据不足"
- 无时间字段：该视角跳过，不强行编造

### 2.5 约束

- 不评价结构问题（占比、构成等）
- 不标记异常值（交给异常视角）
- 预测必须基于明确的历史规律，不编造，标注置信区间
- 节假日/异常日：识别但不剔除，由合成层决定如何处理

## 三、结构分析规则

### 3.1 适用场景

数据中有可拆分的维度（部门/产品线/地域/客户类型等），需要理解"整体的 100% 由哪些部分构成、哪个部分贡献最大"。

### 3.2 分析步骤

1. **识别可拆维度** -- 扫描数据，列出所有可作为分组维度的列
2. **选择拆分维度** -- 如果上层未指定，用"贡献度"原则自动选 Top 2 维度
3. **分组聚合** -- 按选定维度做 GROUP BY 聚合
4. **计算占比与排名** -- 每个分组的份额、Top N、累计贡献度
5. **因子贡献度排名** -- 用 Top N / 帕累托（80/20）等方法找最关键因子
6. **多表关联**（如适用）-- 如果有多张相关表，按主键关联交叉透视
7. **同期对比**（如适用）-- 本期结构 vs 上期结构，看占比变化
8. **结构风险预警** -- 发现单一因子占比过高、过于集中等风险

### 3.3 输出结构

```json
{
  "perspective": "structure",
  "summary": "一句话整体结构判断",
  "dimensions_analyzed": ["部门", "产品线"],
  "findings": [
    {
      "dimension": "部门",
      "top_contributors": [
        { "name": "研发", "value": 320000, "share": "42.1%" },
        { "name": "销售", "value": 240000, "share": "31.6%" }
      ],
      "cumulative_top_n": "Top 2 占 73.7%",
      "pareto_check": {
        "is_pareto": true,
        "comment": "符合 80/20 分布，Top 2 贡献超 73%"
      },
      "concentration_risk": {
        "is_concentrated": true,
        "top_n_share": "Top 2 占 73.7%",
        "comment": "结构集中度偏高，建议关注单点风险"
      },
      "period_comparison": {
        "previous_share": "40.1%",
        "current_share": "42.1%",
        "shift": "+2.0pp",
        "direction": "集中度上升"
      }
    }
  ],
  "table_recommendations": [
    "建议放一张『部门 × 季度』的透视表"
  ]
}
```

### 3.4 降级条件

- 无可拆维度（纯数值列表）：该视角跳过
- 维度过多（>3 个交叉维度）：只挑最关心的 2 个，避免组合爆炸
- 多表 join 失败（key 不匹配/类型不一致）：明确告知，不强行 join

### 3.5 约束

- 不解读时间维度（同期对比可做，但完整趋势交给趋势视角）
- 不评价异常值（发现"某行数据不对劲"时标记后交给异常视角）
- 不替业务做决策（只描述结构事实和风险，不判断"所以要改"）

## 四、异常分析规则

### 4.1 适用场景

任何数据集都适用。异常视角做"侦探工作"：别人看正常的，它看不正常的。

### 4.2 分析步骤

1. **识别数值列** -- 找出所有可以做统计的数值字段
2. **建立基线分布** -- 为每个数值列计算 mean/std/quartiles，建立"正常范围"
3. **统计离群检测** -- 使用以下方法之一或组合：
   - 3σ 法则：超出 μ±3σ 标记为候选异常
   - IQR 四分位距：超出 Q1-1.5×IQR 或 Q3+1.5×IQR 标记为候选异常
   - Z-Score：|z| > 3 标记为候选异常
4. **突变检测** -- 同环比剧烈变化（>50% 变动）、单点跳跃
5. **数据质量扫描** -- 检查：
   - 空值率（整体和分列）
   - 重复率
   - 类型一致性
   - 明显录入错误（负金额、未来日期、零分母等）
6. **业务规则匹配**（如适用）-- 按上层提供的业务规则做合规扫描
7. **重复与冲突检测** -- 同一笔记录出现多次、同一字段值前后不一致
8. **风险分级** -- 按下方标准分级

### 4.3 风险分级标准

| 级别 | 触发条件 | 示例 |
|---|---|---|
| **CRITICAL** | 可能影响业务决策的严重异常 | 负金额、未来日期、单笔超大额、明显数据冲突 |
| **WARN** | 偏离常态但可能合理 | 3σ 离群点、同比变动 >50%、空值集中段 |
| **INFO** | 轻微偏离，仅作记录 | 1.5×IQR 离群点、个别格式不规范 |

### 4.4 输出结构

```json
{
  "perspective": "anomaly",
  "summary": "一句话整体异常评估",
  "total_rows_scanned": 1248,
  "anomaly_count": { "critical": 2, "warn": 6, "info": 14 },
  "findings": [
    {
      "severity": "CRITICAL",
      "type": "outlier|mutation|quality|rule|duplicate",
      "row_index": 423,
      "column": "amount",
      "value": -15800,
      "expected_range": "0 to 50000",
      "explanation": "出现负金额，疑似数据录入错误或退款记录未做特殊标记",
      "suggested_action": "人工复核第 423 行，确认是否为退款"
    }
  ],
  "data_quality": {
    "missing_rate": "1.2%",
    "duplicate_rate": "0.0%",
    "type_inconsistency": []
  }
}
```

### 4.5 降级条件

- 少于 30 行数据：无法做统计离群检测，标注"样本不足"
- 无数值列：只做数据质量扫描，跳过统计离群检测

### 4.6 约束

- 不替业务做决策（只标记异常，不判断"这是错的所以要改"）
- 明确解释 expected_range，让上层能验证判断逻辑
- 单次返回最多 5 个 CRITICAL，超出时按严重度截取
- 不评价趋势/结构（只看"这一行是不是不正常"）

## 五、合成层规则

### 5.1 职责

只有合成层有权把三个视角的发现交叉印证、去重、归类，写成最终报告。

### 5.2 合成步骤

1. **收集三视角输出** -- 等三个视角都完成（或明确标注失败）后再合成
2. **交叉印证** -- 同一发现被多个视角提到时合并，不同视角矛盾时如实标注
3. **去重归类** -- 按重要性排序，CRITICAL 异常 > 趋势拐点 > 结构风险 > INFO
4. **报告结构**：
   - 整体洞察（一句话）
   - 趋势章节
   - 结构章节
   - 异常章节
   - 行动建议（每个章节末尾给"建议下一步"）

### 5.3 失败隔离

如果某视角失败/超时/数据不足：
- 在报告中明确标注"XX 视角未能完成"
- 用其他视角的发现做最大化补救
- 不放弃整份报告

### 5.4 输出规范

- 数据诚实：不编造任何数字，无法判断的地方明确标"待确认"
- 可视化优先：能用图说清楚的不要堆文字
- 行动导向：每个章节末尾给"建议下一步"，不只罗列发现

## 六、与 SmartAsk 的对应关系（摘要）

> 详见 `data-analysis-integration-design.md`

SmartAsk 的四智能体流水线中，**Agent4（业务分析官）** 是分析这一步的承担者。本文档的三视角方法论是对 Agent4 分析能力的增强方向：

| 本文档 | SmartAsk 现有 |
|---|---|
| 趋势分析规则 | Agent4 目前生成"老板视角经营分析"，但无系统化的趋势/结构/异常拆分 |
| 结构分析规则 | Agent4 的 `_build_layered_management_report` 有部分结构分析（层级分布），但无占比/帕累托/集中度 |
| 异常分析规则 | Agent4 目前无异常检测能力 |
| 合成层规则 | Agent4 目前直接生成一段文本，无多视角交叉印证 |

**重要**：本文档仅记录方法论和对应关系，不修改任何代码。集成方式由后续设计文档规划。
