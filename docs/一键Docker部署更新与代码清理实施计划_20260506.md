# SmartAsk 一键 Docker 部署更新与代码清理实施计划

> 日期：2026-05-06  
> 目标：把当前开发机项目整理成“用户机可一键部署、前后端功能完整复刻、代码结构干净可维护”的交付版本。

## 1. 总目标

本次不是简单把项目打包成 Docker，而是要做到用户视角的完整落地：

- 用户机只需要具备 Docker Desktop、Git、可用 `.env`，即可一键启动。
- 前端、后端、PostgreSQL、初始化数据、运行时配置、报告配置、问数流程全部随容器落地。
- 开发机能跑的核心功能，在用户机通过验收清单逐项复刻。
- 项目根目录从“调试脚本堆积态”整理成“可交付工程态”。
- 更新脚本支持后续增量升级，不破坏用户已有数据和配置。

需要明确一点：所谓“100% 一键落地”需要定义边界。Docker 可以保证应用、依赖、数据库初始化和静态资源一致，但 AI API Key、飞书权限、外网访问、Docker Desktop 状态仍属于用户机外部前置条件。计划目标是：前置条件满足后，应用功能 100% 复刻。

## 2. 当前项目现状

### 已具备能力

- 根目录已有 `docker-compose.yml`，包含 `postgres`、`backend`、`frontend` 三个服务。
- 后端已有 `backend/Dockerfile`，容器启动命令为 `python bootstrap.py`。
- 前端已有 `frontend/Dockerfile` 与 `frontend/nginx.conf`，支持 `/api/` 反代到后端，并关闭 SSE buffering。
- 已有 `.env.example`，覆盖端口、AI、PostgreSQL、飞书等关键配置。
- 已有 `deploy.ps1` / `deploy.bat` 和 `update.ps1` / `update.bat`。
- `backend/bootstrap.py` 已支持迁移、运行时配置恢复、Bookshelf 元数据导入、业务数据导入。
- `backend/imports/` 已包含三类初始化包：
  - `bookshelf_bundle.json`
  - `runtime_config_bundle.json`
  - `angel_group_data_bundle.json`
- `scripts/integration_test.py` 已覆盖健康检查、数据源、AI 模型、Bookshelf、Agent、飞书、前端等接口。
- 当前前端 `npm run build` 可通过。
- 当前后端源码 AST 检查可通过。

### 需要补强的问题

- 根目录遗留大量一次性调试脚本，交付包观感不干净。
- `frontend/src/views/` 存在旧页面与备份页面，例如 `Chat.vue`、`SmartAsk - 副本*.vue`。
- `frontend/src/components/HelloWorld.vue` 仍在仓库中，属于 Vite 模板遗留。
- `backend/` 内存在大量手工检查脚本、旧日志、临时测试脚本，需要分流到 `tools/dev/`、`tests/` 或归档。
- `docs/` 内部署文档较多，存在多版本并存，用户容易不知道看哪一份。
- Docker 构建已有基础，但还缺“发布前一键验收矩阵”和“用户机失败诊断包”。
- Vite 构建存在大 chunk 警告，短期不阻断部署，后续需要拆包优化。
- `datasource_router.py` 使用 `pd.read_sql_query(sql, conn)` 有 pandas SQLAlchemy 警告，短期不阻断，长期应优化。

## 3. 交付边界

### 必须 100% 复刻的功能

- 智能问数主页面可访问。
- 数据集自动路由、单数据集自动采用、多候选口径确认逻辑可用。
- 四阶段问数流程可执行：理解问题、加载上下文、生成 SQL、执行 SQL、生成报告。
- SSE 流式事件可显示：中间区精简流程、右侧执行轨迹、SQL 块、最终回答。
- 确认口径后继续问数流程与直接问数流程展示一致。
- 新对话可清空当前任务状态，不残留旧右侧执行轨迹。
- AI 模型管理可增删改查、设置默认模型。
- 数据源管理可增删改查、测试连接。
- 数据集书架、报告配置、Agent 管理页面可访问。
- 飞书同步配置页面可访问；真实同步依赖飞书凭证，凭证缺失时应清晰提示。
- PostgreSQL 数据、Bookshelf 元数据、业务快照数据可初始化。
- 用户关闭容器后重启，已有数据和配置不丢失。

### 不承诺由 Docker 解决的外部条件

- 用户没有 Docker Desktop 或 Docker daemon 未启动。
- 用户没有可用 AI API Key。
- 用户机网络无法访问模型服务或飞书。
- 用户机端口被占用且未修改 `.env`。
- 飞书应用未授权或表格权限不足。
- 模型供应商不返回 `reasoning_content` 一类字段时，前端不能展示真实内部思考，只能展示真实流式内容片段和执行进度。

## 4. 实施阶段

## 阶段 P0：基线冻结与风险保护

目标：先把当前能跑的状态保护住，避免边清理边破坏功能。

执行项：

- 创建交付分支，例如 `release/docker-oneclick-20260506`。
- 记录当前 `git status --short`，确认哪些改动属于本轮 UI/问数优化。
- 先不删除任何代码，只做清单标记。
- 执行当前基线验证：
  - `npm run build`
  - 后端源码 AST 检查
  - `docker compose config`
  - `docker compose up -d --build`
  - `.\deploy.ps1 -RunTests`
- 输出一份 `docs/发布前基线验证记录_YYYYMMDD.md`。

验收标准：

- 前端构建通过。
- 后端健康接口通过。
- Docker 三容器启动成功。
- 集成测试无 FAIL；允许因未配置真实 AI 或飞书导致 SKIP，但必须有明确说明。

## 阶段 P1：Docker 一键部署加固

目标：让用户机部署路径足够傻瓜化，失败也知道怎么修。

执行项：

- 保留当前 `docker-compose.yml` 的三服务架构：
  - `postgres`
  - `backend`
  - `frontend`
- 加强 `deploy.ps1` 前置检查：
  - Docker 是否安装。
  - Docker daemon 是否启动。
  - `.env` 是否存在。
  - `.env` 是否仍是模板占位值。
  - 端口是否被占用。
  - 磁盘空间是否足够。
  - Compose 插件是否可用。
- 加强 `update.ps1`：
  - 支持 `-NoPull`，方便离线包更新。
  - 支持 `-RunTests` 默认在容器内执行。
  - 更新前自动备份 `config/`、PostgreSQL dump、关键 bundle。
  - 更新失败时提示回滚命令。
- 增加 `doctor.ps1`：
  - 一键收集 `docker compose ps`、backend/postgres/frontend 日志、`.env` 脱敏摘要、端口占用、镜像版本。
  - 输出到 `diagnostics/smartask_diagnose_时间戳.zip`。
- 增加 `reset.ps1`：
  - 明确区分“软重启”“重建容器”“清空数据卷”。
  - 清空数据卷必须二次确认。
- 增加 `backup.ps1`：
  - 调用 `scripts/backup_all.py`。
  - 额外备份 PostgreSQL。
  - 输出可迁移备份包。
- 完善 `.env.example`：
  - 每个变量增加中文说明。
  - 明确必填、可选、只在 Docker 中使用、只在本地开发中使用。
- 校验 `frontend/nginx.conf`：
  - SSE 必须 `proxy_buffering off`。
  - `proxy_read_timeout` 不低于 300s。
  - `/api/` 反代路径不能丢失。

验收标准：

- 新机器执行 `.\deploy.ps1 -RunTests` 可完成部署。
- 失败时错误信息能直接指导用户修复。
- 端口冲突、缺少 `.env`、模板 Key 未替换、Docker 未启动等场景均能被前置拦截。

## 阶段 P2：初始化数据与功能复刻验证

目标：保证用户机启动后不是“空壳系统”，而是拥有开发机等价的元数据和业务样例。

执行项：

- 明确 `backend/imports/` 三类 bundle 的来源和刷新方式。
- 每次发布前执行：
  - `python scripts/backup_all.py`
  - 校验 bundle 是否包含最新数据集、提示词、黄金 SQL、报告配置、AI 配置模板。
- 检查 `backend/bootstrap.py` 幂等性：
  - 首次空库导入。
  - 非空库不覆盖用户数据。
  - `-ForceImport` 可覆盖式重导。
  - `-ForceConfig` 可覆盖式重写配置。
- 增强 `scripts/integration_test.py`：
  - 增加 `/api/smart-chat/stream` SSE 测试。
  - 增加 `/api/smart-chat/confirm-by-boss/stream` 测试。
  - 增加 SQL 块返回结构测试。
  - 增加结果报告结构测试。
  - 增加新对话状态清空测试。
- 增加一份人工验收脚本：
  - 打开首页。
  - 输入“东部分公司业绩怎么样”。
  - 检查中间区是否有精简执行流。
  - 检查右侧是否逐节点打印执行轨迹。
  - 检查 SQL 块样式是否为灰底、彩色、高亮、可复制。
  - 检查最终回答是否为老板可读摘要。

验收标准：

- 用户机首次启动后能看到数据集。
- 能完成一次完整问数。
- 直接问数与确认口径后继续问数，右侧轨迹和中间区体验一致。
- 结果报告不会出现空洞废话、重复主语或错误“锁定数据集”措辞。

## 阶段 P3：项目代码清理

目标：让交付代码像正式产品，而不是开发现场。

清理原则：

- 不直接删除，先迁移或归档。
- 每一批清理后都跑构建和部署测试。
- 不清理正在被路由、import、Docker COPY、脚本引用的文件。
- 所有清理动作必须可回滚。

建议清理清单：

| 类别 | 当前位置 | 建议处理 |
| --- | --- | --- |
| 根目录一次性调试脚本 | `analysis_*.py`、`fix_*.py`、`debug_*.py`、`test_*.py` 等 | 迁移到 `_legacy/dev-scripts/` 或删除 |
| 前端旧页面 | `frontend/src/views/Chat.vue` | 若路由长期不用，迁移到 `_legacy/frontend/` |
| 前端备份页面 | `SmartAsk - 副本*.vue` | 删除或迁移到 `_legacy/frontend/` |
| Vite 模板遗留 | `frontend/src/components/HelloWorld.vue` | 删除 |
| 后端旧日志 | `backend/*.log`、`backend/*.err.log`、`backend/*.out.log` | 删除并确保 `.gitignore` 覆盖 |
| 后端手工检查脚本 | `backend/check_*.py`、`backend/test_*.py` | 保留有价值者迁移到 `tests/manual/` 或 `tools/dev/` |
| 重复依赖文件 | `requirements_utf8.txt` | 若无引用则删除 |
| 旧演示目录 | `火山引擎demo/`、`火山引擎/` | 若非运行依赖，迁移到 `_legacy/demo/` |
| 多版本部署文档 | `docs/其他电脑Docker部署操作手册.md` 等 | 合并到一份用户手册 + 一份开发手册 |
| 根级 Streamlit 遗留 | `components/`、`pages/`、`vanna01.py` | 确认无引用后迁移或删除 |

清理验证命令：

```powershell
rg -n "被清理文件名或模块名" .
npm run build
python scripts/verify_deployment.py
.\deploy.ps1 -RunTests
```

验收标准：

- 根目录只保留产品、部署、文档、脚本入口。
- 开发辅助脚本有统一归档位置。
- 前端源码不再有未使用备份页面。
- Docker 构建上下文更小。
- 删除清理后功能不回退。

## 阶段 P4：发布包与版本管理

目标：让开发机更新和用户机更新走同一套发布机制。

执行项：

- 增加版本文件：
  - `VERSION`
  - `backend/version.py`
  - 前端页脚或关于页展示版本。
- 后端 `/api/health` 返回：
  - `version`
  - `build_time`
  - `git_commit`
  - `schema_version`
- 发布前执行：
  - 构建前端。
  - 后端源码检查。
  - Docker build。
  - 集成测试。
  - 生成发布说明。
- 生成两类交付方式：
  - Git 拉取版：用户执行 `git pull && .\update.ps1 -RunTests`。
  - 离线包版：管理员导出 release zip + 镜像 tar + `.env` 模板。
- 增加回滚策略：
  - Git tag 回滚。
  - Docker 镜像 tag 回滚。
  - 数据库备份恢复。

验收标准：

- 任意部署问题都能定位到具体版本。
- 用户机更新前自动备份。
- 更新失败有回滚路径。

## 6. 具体执行顺序

推荐按下面顺序推进，避免越改越乱：

1. 冻结当前可运行版本，打 tag 或建分支。
2. 补齐 `doctor.ps1`、`backup.ps1`、`reset.ps1`。
3. 加强 `deploy.ps1` 和 `update.ps1`。
4. 扩展 `scripts/integration_test.py`，覆盖 SSE 问数和确认口径流程。
5. 在一台干净 Windows 用户机上跑一轮真实部署。
6. 记录失败点，修复部署脚本。
7. 通过后再开始代码清理。
8. 第一批清理前端备份文件和 Vite 模板遗留。
9. 第二批清理根目录一次性脚本。
10. 第三批清理后端手工脚本和旧日志。
11. 合并多版本部署文档。
12. 再跑一轮 Docker 一键部署和人工问数验收。
13. 生成发布说明和回滚说明。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 清理误删仍被引用文件 | 前端构建或后端启动失败 | 每批清理前 `rg` 查引用，清理后跑构建 |
| `.env` 泄露 | 密钥风险 | `.env` 不进 Git，诊断包自动脱敏 |
| 用户机 Docker 网络异常 | 容器无法拉镜像或访问模型 | 提供离线镜像包方案 |
| 数据卷已有旧数据 | 初始化不生效 | 默认保留数据，提供 `-ForceImport` 和重置脚本 |
| AI 模型不返回 reasoning 字段 | 中间区无法展示真实推理字段 | 前端降级展示真实流式内容片段和执行节点 |
| 飞书凭证缺失 | 飞书同步不可用 | 作为可选能力，缺失时清晰提示 |
| 前端大包 | 首屏较慢 | 第二阶段做路由级拆包 |

## 9. 完成定义

当下面条件同时满足时，本轮可以认为完成：

- 干净用户机执行 `.\deploy.ps1 -RunTests` 成功。
- 用户访问 `http://localhost:8080` 可完成完整问数。
- 直接问数、确认口径后继续问数、新对话重置均符合当前 UI 预期。
- `.\update.ps1 -RunTests` 可完成增量更新。
- `doctor.ps1` 能生成可排查诊断包。
- 项目根目录无明显临时脚本堆积。
- 部署文档只保留清晰入口。
- 发布前验收矩阵全部通过或有明确 SKIP 原因。
