# 系统控制台字段级权限与管理看板计划

## 1. 目标

当前控制台已经能控制导航、按钮、数据集范围，但还缺两类能力：

- **显示级权限**：某些页面可以进入，但页面里的敏感字段不一定都能看。例如员工列表里的“组织”“手机号”“书籍信息”“角色”等。
- **运营看板**：超级管理员需要看到系统使用情况、token 用量、报错、低置信度问题，并能一键跳到对应日志定位问题。

建议保持现在“四个固定角色”不变，在控制台新增两层配置：

1. 字段显示权限：控制“看不看得到某个字段/区域”。
2. 管理看板：展示访问、用量、错误、低置信度、慢请求和高风险操作。

不建议现在做完全自定义角色。先把固定角色下的细粒度开关补齐，风险更低。

## 2. 权限分层建议

权限分成四层，控制台里也按这四层展示：

| 层级 | 控制对象 | 示例 | 影响范围 |
| --- | --- | --- | --- |
| 导航权限 | 左侧菜单是否显示 | 数据资产管理、员工权限管理 | 入口级 |
| 操作权限 | 按钮/动作是否可用 | 新增、编辑、删除、保存、导入 | 行为级 |
| 数据权限 | 能看哪些数据集/组织范围 | 命中组织树的数据集 | 数据范围 |
| 显示权限 | 页面字段/区域是否展示 | 员工组织、手机号、角色、SQL、token 用量 | 字段级 |

显示权限只解决“看不看得到”，不替代数据权限。例如业务管理员能进入员工列表查看账号，但可以不展示手机号、组织明细或书籍信息。

## 3. 字段级权限设计

### 3.1 员工权限页

你截图里这类表格建议拆成以下显示权限：

| key | 名称 | 默认开放角色 | 说明 |
| --- | --- | --- | --- |
| `employee_field_id` | 查看员工 ID | super_admin, admin | 普通用户通常不需要 |
| `employee_field_name` | 查看姓名 | super_admin, admin, business_admin | 基础识别字段 |
| `employee_field_phone` | 查看电话 | super_admin, admin | 敏感信息 |
| `employee_field_role` | 查看角色 | super_admin, admin | 你提到的“角色这行” |
| `employee_field_status` | 查看状态 | super_admin, admin | 是否启用 |
| `employee_field_org` | 查看组织 | super_admin, admin, business_admin 可选 | 可细到只显示组织名、不显示编码 |
| `employee_field_org_code` | 查看组织编码 | super_admin, admin | 编码比组织名更敏感 |
| `employee_field_bookshelf` | 查看书籍信息 | super_admin, admin | 若涉及业务范围，建议默认收紧 |
| `employee_field_actions` | 查看操作列 | super_admin, admin | 操作列本身也可隐藏 |

前端行为建议：

- 无权限字段直接隐藏整列，不显示空列。
- 如果为了保持布局必须显示，则展示 `***`，但表格里建议直接隐藏。
- 导出、复制、批量操作也要复用同一套字段权限，避免页面隐藏但导出泄露。

### 3.2 数据资产页

建议新增：

| key | 名称 | 说明 |
| --- | --- | --- |
| `dataset_field_connection` | 查看数据源连接信息 | 控制数据源名称、连接标识 |
| `dataset_field_schema` | 查看表结构/DDL | DDL 可能暴露库表结构 |
| `dataset_field_sql_samples` | 查看 Golden SQL | SQL 可能包含业务口径 |
| `dataset_field_prompt` | 查看 Agent 提示词 | 提示词属于系统资产 |
| `dataset_field_external_config` | 查看外部配置 | 飞书、多维表等外部信息 |
| `dataset_field_row_filter` | 查看行级过滤配置 | 数据权限策略本身也敏感 |

### 3.3 智能问数页

建议新增：

| key | 名称 | 说明 |
| --- | --- | --- |
| `smart_field_execution_trace` | 查看执行轨迹 | 当前已有面板权限，可继续细化 |
| `smart_field_generated_sql` | 查看生成 SQL | 可允许问数但不看 SQL |
| `smart_field_dataset_hit` | 查看命中数据集 | 控制是否显示命中路径 |
| `smart_field_confidence` | 查看置信度 | 控制路由分、结果分 |
| `smart_field_token_usage` | 查看本次 token 用量 | 管理员看，普通用户不看 |
| `smart_field_error_detail` | 查看错误详情 | 普通用户只看友好提示 |

### 3.4 模型与数据源页

建议新增：

| key | 名称 | 说明 |
| --- | --- | --- |
| `ai_field_api_key` | 查看/编辑 API Key | 高敏字段 |
| `ai_field_base_url` | 查看/编辑 Base URL | 高敏字段 |
| `ai_field_provider_config` | 查看模型通道配置 | 管理员以上 |
| `datasource_field_host` | 查看数据源地址 | 高敏字段 |
| `datasource_field_credential` | 查看凭据相关信息 | 默认只超管 |

## 4. 控制台 UI 建议

控制台建议从现在的三个 tab 扩成四个 tab：

1. 管理看板
2. 功能权限控制
3. 字段显示权限
4. 数据集权限控制
5. 日志管理

也可以保留“日志管理”为看板里的入口，但从使用上看，独立 tab 更清楚。

### 4.1 字段显示权限页

展示方式建议：

```text
字段显示权限

员工权限管理  6/9 开放
字段                 超管   管理员   业务管理员   普通用户
姓名                 ✓      ✓        ✓            -
电话                 ✓      ✓        -            -
角色                 ✓      ✓        -            -
组织                 ✓      ✓        ✓            -
组织编码             ✓      ✓        -            -
书籍信息             ✓      ✓        -            -

智能问数工作台  4/6 开放
执行轨迹             ✓      ✓        ✓            -
生成 SQL             ✓      ✓        -            -
命中数据集           ✓      ✓        ✓            ✓
置信度               ✓      ✓        ✓            -
```

字段权限和按钮权限不要混在一起，否则控制台会越来越难读。

### 4.2 字段权限元数据

建议沿用当前 feature flags，不新建复杂 RBAC 表，先扩展 `kind`：

```json
{
  "employee_field_org": {
    "label": "查看员工组织",
    "module": "employee_permissions",
    "module_label": "员工权限管理",
    "kind": "field",
    "enabled": true,
    "roles": ["super_admin", "admin", "business_admin"],
    "order": 310,
    "risk": "medium"
  }
}
```

关键字段：

- `kind=field`：字段显示权限。
- `module`：归属页面。
- `roles`：哪些固定角色可见。
- `risk`：敏感字段标记，电话、API Key、SQL、组织编码建议 medium/high。

## 5. 后端约束

字段权限不能只靠前端隐藏，至少高敏字段要后端裁剪。

建议分两级：

### 5.1 第一阶段：前端隐藏

适合低敏字段，例如：

- 表格列隐藏
- 标签隐藏
- 控制台 UI 区域隐藏

### 5.2 第二阶段：后端脱敏

适合高敏字段，例如：

- 手机号
- API Key
- 数据源连接信息
- 组织编码
- SQL 明细
- token 用量明细

后端接口返回前按字段权限裁剪：

```python
if not can_view_feature("employee_field_phone"):
    employee["mobile"] = ""
```

这样即使用户打开浏览器控制台，也拿不到被收紧的字段。

## 6. 管理看板设计

### 6.1 看板核心指标

顶部四个指标卡：

| 指标 | 说明 | 可点击 |
| --- | --- | --- |
| 今日访问数 | 页面访问或接口访问次数 | 跳日志，筛选访问类 |
| 今日问数次数 | 智能问数提交次数 | 跳日志，筛选问数 |
| 今日 token 用量 | 输入/输出 token 合计 | 跳 token 明细 |
| 今日错误数 | API 错误、模型错误、SQL 错误 | 跳日志，筛选 error |

第二行建议：

| 指标 | 说明 | 可点击 |
| --- | --- | --- |
| 低置信度问题 | 路由置信度/结果置信度低的问题 | 跳日志并定位问题 |
| 平均响应时长 | 问数端到端耗时 | 跳慢请求列表 |
| 活跃用户数 | 今日有行为的账号数 | 跳用户访问列表 |
| 高风险操作数 | 删除、导入、覆盖、重置密码 | 跳审计日志 |

### 6.2 趋势图

建议先做三张图：

- 访问趋势：按小时统计访问数。
- token 趋势：按小时统计输入/输出 token。
- 错误趋势：按小时统计错误数，按错误类型分色。

### 6.3 问题列表

看板底部放两个列表：

#### 低置信度问题

字段：

- 时间
- 用户
- 问题
- 命中数据集
- 路由置信度
- 结果置信度
- 状态
- 操作：查看日志

点击“查看日志”跳到日志管理，并自动带筛选：

```text
/admin-console?tab=logs&trace_id=xxx
```

#### 错误问题

字段：

- 时间
- 用户
- 问题或接口
- 错误类型
- 错误摘要
- trace_id
- 操作：查看日志

## 7. 日志跳转设计

现有日志管理需要支持 URL 参数：

| 参数 | 说明 |
| --- | --- |
| `tab=logs` | 打开日志 tab |
| `trace_id=xxx` | 精确定位某次请求 |
| `level=error` | 筛选错误 |
| `category=smart_ask` | 筛选问数 |
| `low_confidence=1` | 筛选低置信度 |
| `user_id=xxx` | 筛选用户 |
| `date=2026-05-17` | 筛选日期 |

跳转后：

1. 自动切到日志 tab。
2. 自动填入筛选条件。
3. 自动展开命中的第一条日志。
4. 高亮 trace_id 对应行。

## 8. 日志与指标采集字段

建议后端统一记录这些字段：

| 字段 | 说明 |
| --- | --- |
| `trace_id` | 一次问数或一次接口链路的唯一 ID |
| `session_id` | 会话 ID |
| `user_id` | 用户 ID |
| `user_role` | 用户角色 |
| `category` | smart_ask/auth/dataset/admin/ai_model |
| `action` | ask/execute_sql/save_dataset/delete_user |
| `status` | success/error/warning |
| `duration_ms` | 耗时 |
| `input_tokens` | 输入 token |
| `output_tokens` | 输出 token |
| `total_tokens` | 总 token |
| `model_name` | 使用模型 |
| `dataset_ids` | 命中数据集 |
| `route_confidence` | 路由置信度 |
| `answer_confidence` | 答案置信度 |
| `error_type` | 错误类型 |
| `error_message` | 错误摘要 |

低置信度判断建议：

```text
route_confidence < 0.65
或 answer_confidence < 0.7
或 requires_confirmation = true
或 route.candidate_dataset_ids 数量 > 1 且分差很小
```

## 9. 推荐落地顺序

### 阶段 1：字段权限框架

- 新增 `kind=field`。
- 控制台新增“字段显示权限”tab。
- 先接入员工权限页字段：电话、角色、组织、组织编码、书籍信息、操作列。
- 前端隐藏列。

### 阶段 2：后端高敏字段裁剪

- 员工接口裁剪手机号、组织编码。
- 模型接口裁剪 API Key。
- 数据源接口裁剪连接信息。
- 智能问数接口裁剪 SQL 明细和置信度明细。

### 阶段 3：管理看板第一版

- 新增“管理看板”tab。
- 展示今日访问数、问数次数、token 用量、错误数。
- 展示低置信度问题列表和错误列表。
- 点击列表项跳日志。

### 阶段 4：日志跳转与筛选增强

- 日志管理支持 URL 参数。
- 支持 trace_id 精确定位。
- 支持低置信度、错误类型、用户、日期筛选。

### 阶段 5：更多页面字段接入

- 数据资产页。
- 智能问数页。
- 模型配置页。
- 数据源页。
- 飞书同步页。

## 11. 注意事项

- 字段权限不要影响原有数据权限：看不到字段不等于能跨组织看数据。
- 高敏字段必须后端裁剪，前端隐藏只适合低敏显示项。
- 控制台不要把按钮权限和字段权限混在同一个大表里，否则后续会越来越乱。
- 看板里的低置信度问题和错误问题必须能跳日志，否则只能看数，不能排查。
- token 用量如果涉及费用，建议默认只有超管和管理员可见。
