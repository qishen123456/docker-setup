# 宝塔面板部署说明

更新时间：2026-05-08

本文档用于阿里云 Linux + 宝塔面板部署 SmartAsk。

## 1. 推荐架构

推荐让宝塔只负责域名、SSL、反向代理和防火墙，SmartAsk 仍由 Docker Compose 管理。

```text
浏览器
  -> 宝塔 Nginx / HTTPS
  -> http://127.0.0.1:8080
  -> Docker frontend nginx
  -> Docker backend
  -> Docker postgres
```

不要让宝塔直接托管 `frontend/dist`，否则容易出现静态资源版本错乱、按钮无响应、接口路径错误等问题。

## 2. 首次部署

SSH 登录服务器后执行：

```bash
git clone -b docker-setup https://gitee.com/tailin1/volcano-intelligent-questions.git smartask
cd smartask
cp .env.example .env
nano .env
bash deploy.sh
```

至少修改 `.env`：

```text
SMARTASK_SECRET_KEY
SMARTASK_AI_API_KEY
SMARTASK_AI_MODEL
SMARTASK_AI_BASE_URL
SMARTASK_ADMIN_USERNAME
SMARTASK_ADMIN_PASSWORD
SMARTASK_ADMIN_DISPLAY_NAME
```

部署完成后先在服务器本机检查：

```bash
curl http://127.0.0.1:5002/api/health
curl http://127.0.0.1:8080/api/health
curl -I http://127.0.0.1:8080
```

## 3. 宝塔反向代理

在宝塔面板中新建站点或选择已有站点，然后配置反向代理：

```text
目标 URL：http://127.0.0.1:8080
发送域名：$host
```

最终用户访问：

```text
https://你的域名
```

不要代理到：

```text
http://127.0.0.1:5173
```

`5173` 是开发机 Vite 端口，不是 Docker 正式服务端口。

## 4. SSL 配置

SSL 建议在宝塔站点层配置。

SmartAsk Docker 前端容器内部只监听 HTTP `80`，由宝塔负责 HTTPS 终止：

```text
HTTPS 用户请求
  -> 宝塔 Nginx SSL
  -> HTTP 127.0.0.1:8080
```

`.env` 中如果配置飞书回调地址，应填写外部 HTTPS 域名：

```text
BACKEND_URL=https://你的域名
FRONTEND_URL=https://你的域名
```

## 5. 防火墙和安全组

阿里云安全组至少放行：

```text
80
443
```

如果你不通过域名和宝塔反向代理，而是直接访问 Docker 端口，还需要放行：

```text
8080
5002
```

生产环境更推荐只开放 `80/443`，让宝塔转发到本机 `127.0.0.1:8080`。

宝塔防火墙中也需要对应放行。

## 6. SSE 流式接口

智能问数实时输出使用 SSE 流式接口：

```text
/api/smart-chat/stream
/api/smart-chat/confirm-by-boss/stream
```

如果页面能打开、普通接口正常，但问数实时输出卡住，优先检查宝塔反向代理是否启用了缓冲。

需要确保代理不要缓存或缓冲流式响应。Docker 内部前端 Nginx 已配置：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 300s;
```

如果宝塔外层还有自定义 Nginx 配置，也应保持类似设置。

## 7. 按钮全部失效的排查

“页面出来了，但所有按钮点击无效”，优先看浏览器控制台。

常见原因：

- JS 静态资源没加载成功。
- 访问到了宝塔站点目录里的旧静态文件，不是 Docker 前端。
- `/assets/*.js` 返回了 404 或 HTML。
- 宝塔反向代理没有指向 `127.0.0.1:8080`。
- 用户拉到的不是 `docker-setup` 分支最新代码。
- 前端构建漏文件。

服务器侧执行：

```bash
cd smartask
docker compose ps
docker compose logs --tail=200 frontend
docker compose logs --tail=200 backend
curl -I http://127.0.0.1:8080
curl http://127.0.0.1:8080/api/health
```

浏览器侧检查：

- 按 `F12`。
- 看 Console 是否有红色报错。
- 看 Network 是否有 `assets/*.js`、`/api/*` 请求失败。

## 8. 生成诊断包

让服务器管理员执行：

```bash
cd smartask
bash doctor.sh
```

如果怀疑 Docker 构建失败：

```bash
bash doctor.sh --with-build-log
```

把生成的文件发给开发者：

```text
diagnostics/smartask_linux_diagnose_时间戳.zip
```

如果服务器没有 `zip`，会生成：

```text
diagnostics/smartask_linux_diagnose_时间戳.tar.gz
```

## 9. 日常更新

```bash
cd smartask
bash update.sh
```

更新脚本会自动：

- 备份当前配置和数据库。
- 切换 `docker-setup` 分支。
- 拉取最新代码。
- 重新构建 Docker 服务。
- 检查后端健康状态。

## 10. 回滚

查看备份：

```bash
ls -lh backups
```

按备份恢复：

```bash
cd smartask
bash restore.sh --backup-dir backups/时间戳 --confirm
```

默认不会恢复 `.env`，避免覆盖生产密钥。如果确实需要恢复 `.env`：

```bash
bash restore.sh --backup-dir backups/时间戳 --confirm --restore-env
```

## 11. 禁止操作

生产环境不要随便执行：

```bash
docker compose down -v
```

`-v` 会删除 Docker volume，可能导致 PostgreSQL 和 Chroma 数据丢失。
