# SmartAsk 方案归档

更新时间：2026-05-06

本文档整合原 `docs/` 下多份历史方案，保留结论、方向和仍有参考价值的执行要点。原散文档已删除，避免交付时文档入口过多。

## 1. 当前系统定位

SmartAsk 当前是基于四 Agent 链路的智能问数系统：

- Agent1：识别问题意图、路由数据集、处理口径确认。
- Agent2：生成只读 SQL。
- Agent3：复核 SQL 字段、口径、安全性和可执行性。
- Agent4：基于结果生成经营分析报告。

核心后端入口：

- `backend/controllers/smart_chat.py`
- `backend/four_agent_ask.py`
- `backend/report_spec_builder.py`
- `backend/datasource_router.py`

核心前端入口：

- `frontend/src/views/SmartAsk.vue`
- `frontend/src/state/smartAskSession.js`
- `frontend/src/components/smartask/*`

## 2. 火山引擎 DataAgent 参考结论

参考火山引擎 DataAgent 后，当前项目已明确以下体验目标：

- 右侧执行轨迹应逐节点打印，不等全部完成后再展示。
- 中间区应展示精简流程，不复制右侧完整轨迹。
- SQL 块应使用灰底、语法高亮、横向滚动和复制按钮。
- 模型实时输出不应暴露 JSON、SQL 半截、`dataset_id`、`score_hint` 等原始切片。
- 确认口径后继续问数，与直接问数的执行轨迹展示应一致。
- 新对话应清空右侧状态和旧任务残留。

## 3. 报告生成规范

报告生成应遵守：

- 场景识别后再匹配模板。
- 对比场景使用左右对称布局，突出差异值和对比率。
- 单体分析使用 KPI、趋势、细分维度结构。
- 排名场景突出名次和差距。
- 金额统一由前端格式化函数处理。
- 完成率使用红绿灯标准：`>=100%` 绿，`80%-100%` 黄，`<80%` 红。
- 图表默认按完成率降序排序。
- 标题统一为“业绩分析报告”，避免“极简报告”等冗余词。

分析文字结构：

- 核心结论：一句话说清当前状态。
- 亮点分析：用项目符号列出指标、数值和原因。
- 问题诊断：列出缺口、风险和边界。
- 改进建议：给出 1-2 条具体动作。

## 4. 数据集与报告配置解耦

历史方案中关于报告配置解耦的有效结论：

- 数据集元数据、Prompt、Golden SQL、报告展示配置应分层管理。
- 报告模板不应写死在模型输出里。
- 数据集书架应提供字段字典、LLD、样例 SQL、提示词片段。
- ReportSpec 应能表达 KPI、表格、图表、分析文案区域。
- 前端根据 ReportSpec 渲染，而不是让模型自由生成不可控 HTML。

## 5. Autonomous BI 升级方向

长期升级方向：

- 从“回答是什么”升级到“解释为什么”。
- 支持归因分析、异常检测、趋势洞察和行动建议。
- 报告可追溯到 SQL、数据集、字段和口径。
- 每个执行节点可审计、可重跑、可回退。
- 支持企业级权限、日志、诊断和运维。

短期优先级：

1. 稳定问数链路。
2. 稳定 Docker 一键部署。
3. 清理文档和项目结构。
4. 扩充 Golden SQL 和数据集知识。
5. 优化 ReportSpec 渲染。

暂缓事项：

- 大规模重构 `four_agent_ask.py`。
- 引入复杂多租户权限。
- 改动数据库主 schema。
- 对真实模型内部思考做强承诺。

## 6. 飞书集成方向

飞书相关方案归档结论：

- 当前重点是飞书多维表格同步到 PostgreSQL。
- `.env` 中配置飞书 AppID、AppSecret、BaseID、TableID、ViewID。
- 同步配置和状态应在前端可视化。
- 未配置飞书凭证时页面应清晰提示，而不是报错崩溃。
- 企业级 SSO、OAuth、飞书消息通知属于后续增强项。

## 7. Prompt 和数据口径

历史 `提示词和数据.md` 的核心价值：

- Agent2 必须只输出只读 SQL。
- 禁止 `INSERT`、`UPDATE`、`DELETE`、`DROP`、`ALTER` 等写操作。
- 当前主要业务表为 `angel_group_data`，字段在 `fields` JSONB 中。
- 年份口径、时间口径、组织口径需要由数据集配置统一维护。
- SQL 生成、复核、执行、报告都必须保留口径说明。

## 8. 代码清理原则

后续清理项目代码时遵守：

- 先跑构建和集成测试，再清理。
- 不删除正在被路由、import、Docker COPY、脚本引用的文件。
- 每批清理后都跑 `npm run build` 和集成测试。
- 根目录一次性脚本迁移到 `_legacy/` 或 `tools/dev/`。
- 旧 Vue 备份、Vite 模板遗留、历史 demo 在确认无引用后再删。
