> 版本：v1.0（2026-08-29）
> 状态：已评审（CONDITIONAL PASS 后补齐 4 修正），可执行
> 关联：P1 输入理解层（docs/p1-divergent-test-consolidated-2026-08-29.md）、P1-a 影子模式（commit 123022d）

---

## 1. 背景与目标

### 1.1 要解决的真问题

2026-08-29 P1-a 首字母预览上线实测暴露的体验断裂（用户截图实锤）：

- 问「NB的业绩怎么样」，预览条已算出 NB→南部（书架唯一归属 ds=3 商用事业部），**同时**数据集确认卡照弹（商用/消费者/电商三选一）
- 用户困惑："南部不就是商用的，还要我确认数据集干嘛呢"——**预览与路由两层皮，知识没回流**

更深一层：用户对"系统怎么理解我的问题"完全不可见，改错只有两条路——点候选 chip（选择）或重打整句（重问），**没有"就地修正"**。

### 1.2 目标

1. **解析透明化**：问句被解析成 数据集/对象/指标 三槽位，原句片段框出，用户一眼看到"哪里被理解成了什么"
2. **就地可修正**：点框出的槽位 → 原位候选 → 改正直接重跑，≤2 次点击出结果
3. **修正有回报**：修正写回本人别名层，下次命中标"已学习"

### 1.3 与现有卡片的分工（铁律）

| 卡片 | 场景 | 关系 |
|------|------|------|
| 确认卡 | 流水线**中断**、必须用户拍板才能继续（数据集歧义等） | 触发确认卡的消息**不出解析条**（两套候选 UI 不同屏） |
| 解析条 | 结果**已出**，事后可纠 | 只挂在有 `dataset_results` 的消息上 |

## 2. 核心设计（3 个行业优化已采纳）

| 优化 | 行业参考 | 落地 |
|------|---------|------|
| **转述条而非标注条** | Power BI Q&A | 自然语言转述"我理解为：在[商用事业部开单金额]里查[南部分公司]的[开单金额]"，每个 token 可点；不用 `对象[Y]←"原词"` 工程师语言 |
| **原位交互而非弹层** | ThoughtSpot | 槽位下划线 + 原位下拉候选，不做确认卡式弹窗，减少模态切换 |
| **修正闭环可见性** | 留存关键 | 本人修正命中后解析条标"已学习"，让用户感到修正有回报 |

**关键产品决策（PM 评审）**：v1 只读版**不许单独见用户**——"只让看不让改"比没有更挫败。v1 是 v2 的基建，**分期实现、同期发布**。

## 3. 技术方案

### 3.1 parse_spans 聚合

- 位置：**smart_chat 响应聚合层统一拼装**（不进流水线），任何异常整体降级不输出（fail-open 硬原则）
- 数据结构：`parse_spans: [{span_text, slot: dataset|node|metric, resolved_value, start, end, confidence}]`
- 数据基础（代码实锤）：`query_intent` + `resolved_entities` 已在 `ask()` 最终结果的 `dataset_results` 里（`four_agent_ask.py:9268-9269`）

### 3.2 span 定位（"哪个字被解析成了对象"）

三来源，优先级递减：

1. **typo 滑窗 offset**：`typo_fastpath` 滑窗的 start/end（**需 Phase 0.1 透出后才可用**，见 §6 修正 1）
2. **书架别名 find() 定位**：用命中的别名/resolved_value 在原句 `find()`，带**"已占用区间"去重**（同一词出现两次时按 span 顺序消费）
3. **resolved_entities**：路由层已解析的实体

**红线**：定位失败即丢弃该 span，宁可缺不可错框。**弃用**让 LLM 返回 span（幻觉不可靠）。

### 3.3 v2 结构化直跑通道

- **新建通道，不复用 confirm-by-boss**（其内存 session + 数据集选项硬编码不适用于正常直出场景）
- 行为：覆盖 `query_intent` + 强制 `decision=generate_sql` + **跳过 Agent1**（不重走 NL 解析，否则修正成果被 LLM 再解释漂移）
- **权限红线**：跳过 Agent1 ≠ 跳过权限过滤——必须重过 `allowed_dataset_ids` / `_filter_route_by_allowed_datasets`（`four_agent_ask.py:9365`），否则用户在解析条改数据集槽 = 越权查询漏洞（见 §6 修正 2）

### 3.4 修正写回学习

- **绝不直接写书架**（全员污染）。写 `user_alias_feedback` 表（user_id + 原片段 + 修正值），仅对**本人**叠加生效
- 达阈值进管理员审核队列，批准后合并进书架，全程审计日志
- 表必须进 `migrations/`（禁止请求处理器内联 DDL——别成第四个 angel_group_data 事故，审计 L-01/L-02，见 §6 修正 3）
- **通道归属**：feedback 通道收编进 P1 双通道并轨范围，挂在统一消解层，不长出第三条游离通道（6.3 节已实锤双通道分裂待并轨，见 §6 修正 4）

### 3.5 多轮追问的解析条语义

追问场景（「那他的呢」）实体来自上下文继承，原句**没有字面出现**，find() 必失败：

- **不硬找 span**，该槽位标注"**继承自上文第 N 条**"
- 覆盖率验收分母明确定义：仅统计有 `dataset_results` 的消息，追问继承按本语义计入（见 §6 修正 1 延伸）

## 4. 落地计划（分期，v1+v2 同期发布）

### Phase 0：前置修正（不堵洞不动主功能）

| # | 任务 | 对应评审修正 |
|---|------|------------|
| 0.1 | `typo_fastpath.detect` 返回补 `start/end` + early_clarify 透传 | 修正 1：offset 现为循环局部变量，"直接复用"不成立 |
| 0.2 | 直跑通道权限过滤红线写入设计（本文档 §3.3 已落实） | 修正 2：越权漏洞 |
| 0.3 | `user_alias_feedback` 迁移落点（本文档 §3.4 已落实） | 修正 3：部署事故防范 |
| 0.4 | 多轮追问解析条语义（本文档 §3.5 已落实） | 修正 4：覆盖率验收保护 |

### Phase 1：v1 基建（不单独发布）

- 响应层聚合 parse_spans（fail-open 整体降级）
- span 定位三来源（§3.2）
- 前端转述条：自然语言 + token 可点 + 低置信标红
- 确认卡消息不出条（铁律 §1.3）

**验收（机器可执行）**：
- 解析条覆盖率 ≥95%（分母按 §3.5 定义）
- span 定位准确率 ≥90%（失败丢弃不猜）
- qa 冒烟 18 断言 + 单测 37 条零退化

### Phase 2：v2 核心（与 v1 同期发布，只做对象/数据集两槽）

- 对象/数据集槽**原位下拉编辑**，候选分层：书架别名+拼音索引 / confirmation_options
- 结构化直跑通道（§3.3，含权限过滤红线）
- "改一词出结果" ≤2 次点击

**验收（机器可执行）**：
- 修正后局部重跑成功率 ≥98%
- **权限红线专项用例**：数据集槽改成无权数据集必须被拒
- Agent1 其他路径回归 0 影响

### Phase 3：v2.5（修正闭环）

- 指标槽编辑
- `user_alias_feedback` 本人叠加 + "已学习"标记 + 管理员审核合并书架（审计日志）
- feedback 通道收编进 P1 双通道并轨（§3.4）

## 6. 评审修正记录（4 条，已全部并入本文档）

> 来源：三方正验（2026-08-29）。原方案"技术点确认"有 1 处失实 + 3 个漏坑，修正如下：

1. **typo offset"直接复用"失实** → 滑窗 start/end 是循环局部变量，返回字典只有 `fragment/suggestion/node_name`。Phase 0.1 透出后才可用，且 early_clarify 需透传。追问场景 find() 必失败 → §3.5 继承语义保护覆盖率验收
2. **直跑跳过 Agent1 = 跳过权限过滤** → §3.3 红线：必须重过 `allowed_dataset_ids`
3. **user_alias_feedback 迁移缺失风险** → §3.4：进 `migrations/`，禁内联 DDL
4. **feedback = 第三条消解通道** → §3.4：收编进 P1 双通道并轨，不游离

## 7. 风险与边界

| 风险 | 应对 |
|------|------|
| span 错框误导用户 | 定位失败即丢弃（§3.2 红线）；低置信标红 |
| 直跑通道污染 Agent1 路径 | 新建独立通道；回归基线（qa 冒烟 18 断言）每期必跑 |
| 反馈表全员污染 | 本人叠加 + 审核合并（§3.4） |
| v1 单独上线挫败感 | v1+v2 同期发布（§2 产品决策） |
| 追问场景解析条退化 | §3.5 继承语义，不假装没有 |
