# 运行态配置导出导入操作手册

本文档用于数据源、数据集、字段字典、Golden SQL、Agent 提示词、AI 模型配置、报告模板、员工权限等运行态资源的迁移发布。

适用场景：

- Windows 测试环境调好了数据集和提示词，需要发布到 Linux 正式环境。
- 代码经常更新，但正式环境已有配置不能丢。
- 误导入、误覆盖后，需要用导入前自动备份回滚。

## 1. 推荐原则

- 只改前后端代码：走 Git + Docker 重建，不导入运行态配置。
- 改了数据源、数据集、提示词、报告模板：先导出运行态包，再到目标环境预检和导入。
- 正式环境导入前默认自动备份，备份包在 `backups/runtime/`。
- 不导出用户登录 token、问数历史、`.local.json`、`.env`。

## 2. 前端页面操作

入口：

```text
左侧菜单 -> 迁移发布管理
```

权限：

```text
只有超级管理员可见和可操作。
```

### 2.1 从测试环境导出

1. 登录测试环境网页。
2. 进入 `迁移发布管理`。
3. 点击 `导出运行态包`。
4. 保存下载的 `smartask_runtime_时间戳.json`。

导出包包含：

- `config/datasources.json`
- `config/ai_settings.json`
- `config/feishu_sync.json`
- `config/sql_prompts.json`
- `config/app_config.json`
- `config/employee_permissions.json`
- `bs_datasets`
- `bs_data_dictionary_items`
- `bs_golden_sql_samples`
- `bs_agent_prompt_fragments`
- `bs_dataset_report_config`
- 其他数据书架运行态表

### 2.2 到正式环境预检

1. 登录正式环境网页。
2. 进入 `迁移发布管理`。
3. 选择刚才导出的 JSON 文件。
4. 默认选择 `合并导入`。
5. 点击 `预检导入`。

预检会显示：

- 哪些 JSON 配置会新建、跳过或覆盖。
- 每张书架表现有多少条、导入多少条。
- ID 是否有重合。
- 当前选择是合并模式还是替换模式。

### 2.3 正式导入

确认预检结果没问题后：

1. 保持 `合并导入`。
2. 一般不要打开 `覆盖已有 JSON 配置`，除非明确要用测试环境配置覆盖正式环境。
3. 点击 `确认导入`。

系统会先自动生成当前正式环境备份包：

```text
backups/runtime/runtime_backup_时间戳.json
```

导入完成后，如发现配置不对，可用这个备份包再导入回滚。

## 3. 命令行操作

### 3.1 Windows 测试环境导出

```powershell
cd smartask
python scripts/export_runtime_config.py --output runtime_config_20260507.json
```

命令解释：

- `cd smartask`：进入项目目录。
- `python scripts/export_runtime_config.py`：调用后端导出逻辑。
- `--output runtime_config_20260507.json`：指定导出的运行态包文件名。

### 3.2 Linux Docker 正式环境预检

先把导出包上传到服务器项目目录，例如：

```bash
scp runtime_config_20260507.json user@server:/opt/smartask/
```

在服务器执行：

```bash
cd /opt/smartask
docker compose cp runtime_config_20260507.json backend:/app/runtime_config_20260507.json
docker compose exec backend python /app/scripts/import_runtime_config.py --input /app/runtime_config_20260507.json --mode merge --dry-run
```

命令解释：

- `docker compose cp`：把宿主机 JSON 包复制到后端容器。
- `--mode merge`：合并导入，不主动清空目标书架表。
- `--dry-run`：只预检，不写入任何配置和数据库。

### 3.3 Linux Docker 正式环境导入

预检确认后执行：

```bash
docker compose exec backend python /app/scripts/import_runtime_config.py --input /app/runtime_config_20260507.json --mode merge
```

命令解释：

- 默认会自动备份当前正式环境运行态配置。
- 默认不会覆盖已存在的 JSON 配置文件。
- 数据书架表按 ID 或自然键合并更新。

如果你明确要覆盖已有 JSON 配置：

```bash
docker compose exec backend python /app/scripts/import_runtime_config.py --input /app/runtime_config_20260507.json --mode merge --overwrite-configs
```

如果你明确要用导入包替换整套书架配置：

```bash
docker compose exec backend python /app/scripts/import_runtime_config.py --input /app/runtime_config_20260507.json --mode replace --overwrite-configs
```

注意：`replace` 会先清空书架运行态表，再写入导入包。生产环境只建议在完整备份后使用。

## 4. 回滚操作

导入前自动备份目录：

```text
backups/runtime/
```

回滚步骤：

```bash
cd /opt/smartask
docker compose cp backups/runtime/runtime_backup_时间戳.json backend:/app/runtime_backup_rollback.json
docker compose exec backend python /app/scripts/import_runtime_config.py --input /app/runtime_backup_rollback.json --mode replace --overwrite-configs
docker compose restart backend
```

命令解释：

- 第一行进入正式环境项目目录。
- 第二行把备份包复制进后端容器。
- 第三行用备份包替换恢复运行态配置。
- 第四行重启后端，让 JSON 配置重新加载。

## 5. 发布代码时如何保护正式配置

只发布代码：

```bash
cd /opt/smartask
git pull --ff-only
docker compose up -d --build
curl http://localhost:5002/api/health
```

不要执行会覆盖 `config/`、PostgreSQL volume 或 `.env` 的命令。

如果这次代码发布同时包含运行态调整：

```text
先在测试环境导出运行态包 -> 正式环境预检 -> 正式环境导入 -> 再验证问数。
```

## 6. 备份边界

运行态包适合迁移配置，不适合替代完整数据库灾备。

正式环境仍建议定期做完整备份：

```bash
cd /opt/smartask
mkdir -p backups
docker compose exec -T postgres pg_dump -U postgres -d postgres > backups/smartask_pg_$(date +%Y%m%d_%H%M%S).sql
tar -czf backups/smartask_config_$(date +%Y%m%d_%H%M%S).tar.gz config
```

运行态包解决“配置迁移和快速回滚”，`pg_dump` 解决“整库级灾难恢复”。两者都要保留。
