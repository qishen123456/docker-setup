# SmartAsk / 智能问数 提示词测试用例集

> 配套 `提示词体检报告.md`。目标：把提示词质量从「凭感觉调优」变成「可量化回归」。
> 用法：可作为人工评审清单，也可接入 `backend/batch_test_questions.py` 的 `QUESTIONS` 列表与 copilot 的 `regression_cases`。

---

## 0. 通用断言约定

| 符号 | 含义 |
|---|---|
| ✅ 通过 | 实际输出满足「预期行为」全部断言 |
| ❌ 失败 | 任一断言不满足，记录差异并回滚该提示词改动 |
| 🔍 需人工 | 输出需业务人员肉眼判断（如可视化是否生动），不强制自动化 |

**回归门槛**：第 1–6 类全量通过；第 7 类（copilot 契约）通过；相对 `batch_test_questions.py` 既有基线准确率不下降。

---

## 1. A 类 — 时间锚点 / 防写死年份（P1，硬测试）

> 核心验证：把测试桩「当前日期」设为**非 2026**（如 `2027-03-01`），确认 SQL 年份跟随运行时，而非写死 2026。

| 编号 | 输入 | 预期行为 / 断言 | 风险 |
|---|---|---|---|
| A1 | 今年各分公司的年度开单是多少？ | SQL 的年份条件 = 注入的当前年（2027）；**不得**出现与运行时不相关的字面 `2026` | 🔴 |
| A2 | 和去年比，达成率变化如何？ | 去年 = 2026；SQL 用 `当前年-1` 推导，不写死 | 🔴 |
| A3 | 上月各代表处业绩 | 上月 = 2027-02；区间用 `date_trunc` 推导，不写死 | 🔴 |
| A4 | 最近 7 天的新增线索 | 基于 `CURRENT_DATE` 动态计算，不依赖训练语料默认时间 | 🟠 |

**自动化建议**：在测试桩中 mock `date.today()` 返回 `2027-03-01`，对 A1–A3 做正则断言：SQL 含 `2027`/动态表达式，且不含孤立的 `2026`（除非数据集确实只含 2026 数据且问题显式点名 2026）。

## 2. B 类 — 防臆造 / schema 约束（P2）

| 编号 | 输入 | 预期行为 / 断言 | 风险 |
|---|---|---|---|
| B1 | 查一下用户的「幸运值」字段 | 不得臆造 `幸运值`；应提示该字段不存在或请求澄清 | 🟠 |
| B2 | 统计其他库的订单表 | 只使用**本数据集**已登记表；不得跨库引用未授权表名 | 🟠 |
| B3 | 用未登记的 fields JSONB 子键 | 不得臆造子键；以 DDL/口径为准 | 🟡 |

---

## 3. C 类 — 关联正确性（同名不同义）（P2）

| 编号 | 输入 | 预期行为 / 断言 | 风险 |
|---|---|---|---|
| C1 | 按项目汇总研选+朴邻业绩 | `project_code` 不同义，必须走映射表转换后再 JOIN；不得同名直接 JOIN | 🟠 |
| C2 | 关联维度表获取服务站下项目 | 以 DDL 字段注释/口径确认关联键；语义不确定时先检索或澄清 | 🟠 |

---

## 4. D 类 — 维度完整性 / 层级隔离（P2）

| 编号 | 输入 | 预期行为 / 断言 | 风险 |
|---|---|---|---|
| D1 | 某服务站下各项目的业绩对比 | 维表为基表，最终结果形如 `dim_* LEFT JOIN fact_agg_*`；无事实的项目用 `COALESCE(...,0)` 补 0，不得丢失维度成员 | 🟠 |
| D2 | 统计某分公司的汇总（不含下级明细） | 排除下级字段（如 `业务代表 IS NULL`），防止个人明细累加导致数据翻倍（层级隔离） | 🟠 |
| D3 | 各类型线索量对比 | 「类型」展开为多列指标（条件聚合 `FILTER/CASE WHEN`），不进入 `GROUP BY` 产生多行 | 🟡 |

---

## 5. E 类 — 可视化触发（P2）

| 编号 | 输入 | 预期行为 / 断言 | 风险 |
|---|---|---|---|
| E1 | 各渠道有效线索量及占比（≥3 渠道） | **必须**调用 `generate_visualization` 生成 ≥1 图，图后补 2–3 句业务解读 | 🟠 |
| E2 | 某服务站单月总业绩（单值） | 可不画图，用结构化文字 + 表格说明 | 🟡 |
| E3 | 按月趋势（≥3 时间点） | 必须用折线/柱状图展示趋势 | 🟠 |

---

## 6. F 类 — 多数据集路由消歧（Agent1）（P2）

| 编号 | 输入 | 预期行为 / 断言 | 风险 |
|---|---|---|---|
| F1 | 实体名命中多个数据集（如「业绩」跨商用/电商） | 抛 `confirmation_question` + 2–4 个 `options`（含 `dataset_id` 与 `scope_filter`）；置信度高时禁止追问 | 🟠 |
| F2 | 追问「那东部呢」「跟去年比」 | 沿用上一轮数据集/主体/维度（指代消解），不重新铺开 | 🟠 |

---

## 7. G 类 — Copilot 输出契约（元提示词回归）（P2）

> 验证 `copilot_prompts.py` 生成的 payload 满足落库校验，且不再写死年份。

| 编号 | 检查项 | 断言 |
|---|---|---|
| G1 | JSON 可解析 | `json.loads(payload)` 不抛异常，无 markdown/注释/代码块包裹 |
| G2 | 字段齐全 | 含 `synonyms / lld_documents / schema_definition / data_dictionary / table_relations / golden_sql_samples / agent_prompts / common_questions / regression_cases / report_config` |
| G3 | 数量门槛 | `lld_documents ≥ 1`、`schema_definition ≥ 1`、`golden_sql_samples ≥ 3`、`agent_prompts == 4`（agent_no 1–4 全） |
| G4 | 时间不写死 | 生成的 Agent2 prompt 中，相对时间用「运行时当前年」表述，不得出现孤立 `2026` |
| G5 | 禁臆造 | 生成的 SQL 全中文别名、只用底稿出现的字段；`agent_prompts` 含层级隔离（Agent2）与可执行动作（Agent4）约束 |

## 8. 与现有测试底座的集成

### 8.1 接入 `backend/batch_test_questions.py`
现有 `QUESTIONS` 列表可直接追加本集 A–F 类用例（建议新建 `prompt_regression_questions.py`，复用 `ask_flow_controller`）：

```python
# prompt_regression_questions.py（示意）
from ask_flow import ask_flow_controller
from ask_flow.contracts import AskRequest

QUESTIONS = [
    "今年各分公司的年度开单是多少？",        # A1
    "和去年比，达成率变化如何？",             # A2
    "某服务站下各项目的业绩对比",             # D1
    "各渠道有效线索量及占比",                 # E1
    # ... 追加 A–F 全部用例
]

def run():
    controller = ask_flow_controller.AskFlowController()
    for q in QUESTIONS:
        req = AskRequest(question=q, current_date="2027-03-01")  # 注入非 2026 当前日期
        resp = controller.ask(req)
        # 按本集断言逐项校验，汇总通过率
```

### 8.2 接入 copilot `regression_cases`
在 copilot 生成的 payload 中，`regression_cases` 至少覆盖：单体 / 下钻 / 对比 / 排名 / 时间锚点（A 类）五类，格式沿用现有 schema：
```json
{"question_text": "今年各分公司年度开单", "expected_intent": "aggregation",
 "expected_sql_keywords": ["2027", "CURRENT_DATE"], "sort_order": 1}
```

## 9. 成功标准（回归门槛）

1. A 类（时间锚点）100% 通过 —— 这是本次升级最容易回归的点，必须守住。
2. B/C/D 类（防臆造 / 关联 / 维度完整性）通过率 ≥ 95%。
3. E 类（可视化触发）触发准确率 100%（该画必须画，不该画不画）。
4. F 类（路由消歧）在歧义场景下 100% 抛出确认。
5. G 类（copilot 契约）100% 通过，且重生成后不引入写死年份。
6. 相对 `batch_test_questions.py` 既有问答基线，Top-1 准确率不下降。
