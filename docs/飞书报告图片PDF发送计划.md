# 飞书报告图片与 PDF 发送计划

## 一、目标

在智能问数报告生成后，支持用户将当前报告以图片和 PDF 的形式发送到飞书联系人或群组。

目标体验：

1. 用户在报告区域点击“发送飞书”，或右键报告选择“发送到飞书”。
2. 系统弹出发送面板，用户选择联系人或群组。
3. 系统把当前 HTML 报告导出为图片和 PDF。
4. 后端上传图片和 PDF 到飞书。
5. 飞书机器人把报告发送给目标联系人或群组。
6. 系统记录发送日志，便于追踪谁发了什么、发给谁、是否成功。

## 二、现有项目能力判断

当前项目里已经具备部分飞书基础能力：

| 已有能力 | 代码位置 | 是否可复用 |
|---|---|---|
| 飞书 App ID / App Secret 配置 | `.env.example`、`controllers/auth.py`、`feishu_sync_service.py` | 可复用 |
| tenant_access_token 获取 | `backend/feishu_sync_service.py` | 可复用或抽成公共服务 |
| 飞书免登 | `backend/controllers/auth.py`、`frontend/src/utils/feishu.js` | 可参考 |
| 飞书多维表同步 | `backend/controllers/feishu_sync.py`、`backend/feishu_sync_service.py` | 只和取数相关，不能直接发送报告 |
| 系统日志 | `backend/system_log_store.py` | 可复用 |
| 权限与功能开关 | `backend/feature_flags.py`、RBAC 配置 | 可扩展 |

结论：

> 现有脚本和代码里的应用信息“够拿飞书 token”，但不一定“够发消息”。  
> 如果同一个飞书自建应用已经开通机器人、消息发送、图片上传、文件上传、联系人/群组查询权限，就可以复用现有 App ID / App Secret。  
> 如果现在这个应用只开了多维表格同步权限，那么还需要在飞书开放平台补权限并重新发布应用。

## 三、飞书侧需要确认的配置

### 1. 自建应用基础信息

必须具备：

- `FEISHU_APP_ID` 或 `SMARTASK_FEISHU_APP_ID`
- `FEISHU_APP_SECRET` 或 `SMARTASK_FEISHU_APP_SECRET`
- 应用已发布到企业
- 应用可见范围包含需要接收报告的用户

### 2. 机器人能力

需要确认：

- 自建应用已启用机器人能力。
- 如果要发群聊，机器人需要在目标群里，或应用具备对应群消息权限。
- 如果发给单个用户，用户需要在应用可见范围内。

### 3. 需要申请的权限

按一期能力，建议申请以下方向的权限：

| 能力 | 用途 |
|---|---|
| 发送消息 | 机器人发送文本、卡片、图片、文件消息 |
| 上传图片 | 上传报告 PNG，获取 `image_key` |
| 上传文件 | 上传报告 PDF，获取 `file_key` |
| 获取用户信息或搜索用户 | 前端选择联系人时使用 |
| 获取群组或搜索群组 | 前端选择群组时使用 |

具体权限名称以飞书开放平台后台展示为准。权限申请后通常需要重新发布应用。

## 四、推荐产品形态

### 一期入口

报告右上角增加一个按钮：

```text
发送飞书
```

报告区域右键菜单增加：

```text
发送到飞书
导出图片
导出 PDF
复制核心结论
```

说明：

- 右键适合桌面端。
- 按钮适合飞书内嵌页面、移动端和普通浏览器。
- 不建议只做右键，因为飞书客户端或移动端对右键体验不稳定。

### 发送面板

发送面板包含：

| 字段 | 说明 |
|---|---|
| 接收对象 | 支持联系人和群组 |
| 发送格式 | 图片、PDF、图片 + PDF |
| 附带摘要 | 默认附带报告标题和核心结论 |
| 发送按钮 | 点击后开始导出和发送 |

### 飞书消息样式

建议发送三部分：

1. 一条简短文本或卡片摘要。
2. 一张报告长图，群里可以直接预览。
3. 一个 PDF 文件，方便正式留档和转发。

## 五、技术方案

### 1. HTML 报告作为唯一展示源

当前报告本身是前端 HTML/CSS 渲染结果。不要在后端重新手写一套报告模板，否则样式容易不一致。

推荐方案：

- 前端继续负责报告展示。
- 后端新增一个“报告导出专用页面”或“导出 HTML 模板”。
- 后端使用 Playwright 打开导出页面。
- Playwright 截图生成 PNG。
- Playwright 打印生成 PDF。

### 2. 为什么不用复制链接

复制链接只有在报告有独立详情页、独立 `report_id`、权限校验和持久化记录时才有价值。

当前更适合先做“导出即发送”：

- 不依赖对方是否登录系统。
- 飞书里能直接预览。
- PDF 可以长期留档。
- 不需要为了分享先建设完整报告详情页。

### 3. 不建议每次问数都自动导出

图片和 PDF 生成比较重，不应该在每次问数完成时自动执行。

建议规则：

| 场景 | 是否导出 |
|---|---|
| 普通问数完成 | 不自动导出 |
| 用户点击导出图片 | 临时生成 PNG |
| 用户点击导出 PDF | 临时生成 PDF |
| 用户点击发送飞书 | 临时生成 PNG / PDF 并发送 |
| 发送成功后 | 临时文件保留 1 到 7 天后清理 |

## 六、后端接口设计

### 1. 报告导出接口

```text
POST /api/smartask/reports/export
```

请求示例：

```json
{
  "question": "商用事业部整体达成率是多少",
  "report": {},
  "format": "pdf"
}
```

返回：

```json
{
  "success": true,
  "export_id": "exp_xxx",
  "format": "pdf",
  "file_name": "智能问数报告.pdf",
  "size": 123456
}
```

说明：

- `report` 可以先传当前前端已有的结构化报告数据。
- 后续如果有 `report_id`，再改为通过 `report_id` 导出。

### 2. 飞书接收对象搜索接口

```text
GET /api/feishu-share/receivers?keyword=刘&type=all
```

返回：

```json
{
  "users": [],
  "chats": []
}
```

说明：

- 一期如果飞书搜索权限暂时不足，可以先手动输入 `open_id`、`user_id`、`chat_id` 测试。
- 正式版再做联系人和群组搜索 UI。

### 3. 飞书发送接口

```text
POST /api/feishu-share/report
```

请求示例：

```json
{
  "receivers": [
    {"type": "user", "id_type": "open_id", "id": "ou_xxx"},
    {"type": "chat", "id_type": "chat_id", "id": "oc_xxx"}
  ],
  "send_formats": ["image", "pdf"],
  "report_payload": {},
  "summary": "商用事业部整体达成率 15.44%，剩余缺口 3.85 亿。"
}
```

返回：

```json
{
  "success": true,
  "sent": 2,
  "failed": 0,
  "logs": []
}
```

## 七、后端模块规划

建议新增模块：

| 模块 | 职责 |
|---|---|
| `backend/feishu_client.py` | 获取 token、上传图片、上传文件、发送消息 |
| `backend/report_exporter.py` | 使用 Playwright 导出 PNG/PDF |
| `backend/controllers/feishu_share.py` | 提供发送报告相关 API |
| `backend/report_share_store.py` | 记录发送日志、导出文件元数据 |

建议复用模块：

| 模块 | 复用方式 |
|---|---|
| `secret_codec.py` | 解密飞书 App Secret |
| `system_log_store.py` | 记录发送成功/失败 |
| `auth_store.py` | 获取当前登录用户 |
| `feature_flags.py` | 控制发送能力是否开放 |

## 八、前端改造计划

### 1. SmartAsk 报告区

在报告区域增加：

- 右上角“发送飞书”按钮。
- 报告容器右键菜单。
- 导出中、上传中、发送中状态提示。

### 2. 新增发送弹窗

弹窗内容：

- 搜索联系人/群组。
- 已选择对象列表。
- 发送格式选择：图片、PDF、图片 + PDF。
- 摘要预览。
- 确认发送。

### 3. 失败提示

需要把飞书返回错误翻译成中文：

| 飞书失败场景 | 前端提示 |
|---|---|
| 机器人不在群里 | 机器人未加入该群，无法发送 |
| 用户不在应用可见范围 | 当前应用无法给该用户发送消息 |
| 权限不足 | 飞书应用缺少发送消息或上传文件权限 |
| 文件过大 | 报告文件过大，请改用 PDF 或减少明细 |
| token 失效 | 飞书授权已失效，请检查应用配置 |

## 九、依赖与部署影响

### 1. Python 依赖

需要新增：

```text
playwright
```

并在 Docker 镜像里安装浏览器运行依赖。

注意：

- Playwright 会让 Docker 镜像变大。
- Linux 服务器需要安装 Chromium 依赖。
- PDF/截图生成会增加 CPU 和内存消耗。

### 2. Docker 影响

后端 Dockerfile 需要增加：

```text
playwright install chromium
```

以及必要系统库。

### 3. 临时文件目录

建议新增：

```text
backend/exports/
```

并加入清理策略。该目录不要提交 Git。

## 十、缓存与存储策略

不做长期缓存，避免空间膨胀。

建议：

| 文件类型 | 保留策略 |
|---|---|
| 临时 PNG | 默认 24 小时 |
| 临时 PDF | 默认 7 天 |
| 发送日志 | 长期保留或按系统日志策略保留 |
| 报告原始数据 | 一期不强制持久化 |

清理策略：

```text
每天凌晨清理过期导出文件
```

## 十一、实施阶段

### 阶段 1：验证飞书发送链路

目标：证明当前 App ID / App Secret 是否够用。

任务：

1. 抽出 `feishu_client.py`。
2. 使用现有 App ID / App Secret 获取 token。
3. 手动上传一张测试图片。
4. 手动上传一个测试 PDF。
5. 手动发送到一个测试用户或测试群。

验收：

- 飞书能收到图片。
- 飞书能收到 PDF。
- 失败时能看到明确错误。

### 阶段 2：实现报告导出

目标：把当前 HTML 报告导出为 PNG 和 PDF。

任务：

1. 新增导出页面或导出模板。
2. 后端接入 Playwright。
3. 支持长图截图。
4. 支持 PDF 导出。
5. 控制导出宽度、分页和字体。

验收：

- 图片样式接近当前页面。
- PDF 不截断关键内容。
- 中文字体正常。

### 阶段 3：前后端打通发送

目标：用户可以从报告页发送到飞书。

任务：

1. 新增发送按钮和右键菜单。
2. 新增发送弹窗。
3. 接入后端发送接口。
4. 发送成功/失败提示。
5. 写入系统日志。

验收：

- 可以发给测试用户。
- 可以发给测试群。
- 可以选择图片、PDF、图片 + PDF。

### 阶段 4：权限、日志与清理

目标：生产可用。

任务：

1. 增加功能权限：`smartask_report_share_feishu`。
2. 记录发送日志。
3. 增加导出文件清理任务。
4. 宝塔和 Docker 部署文档补充 Playwright 依赖。

验收：

- 无权限用户看不到发送入口。
- 管理员能看到发送日志。
- 临时文件能自动清理。

## 十二、优先级建议

建议先做最小闭环：

1. 不做联系人搜索，先支持输入测试 `open_id/chat_id`。
2. 先导出 PDF，再导出 PNG。
3. 先发送到一个固定测试群。
4. 确认飞书权限和文件上传链路无误后，再做完整 UI。

原因：

- 飞书权限最容易卡住。
- Playwright 在服务器里的依赖也需要先验证。
- 先打通链路，比一开始做完整联系人 UI 更稳。

## 十三、最终判断

现有应用信息是否够用：

| 情况 | 判断 |
|---|---|
| 已有 App ID / App Secret | 基础够用 |
| 只用于飞书多维表同步 | 不够，需要补消息/图片/文件权限 |
| 已启用机器人并发布 | 可以继续推进 |
| 要发群聊但机器人不在群里 | 不够，需要把机器人加入群 |
| 要搜索联系人/群组 | 需要额外通讯录/群组权限 |

推荐实施口径：

> 先复用现有飞书自建应用的 App ID / App Secret，做一次最小发送验证。  
> 如果 token、上传图片、上传 PDF、发送测试群都成功，就说明现有应用可复用。  
> 如果飞书返回权限错误，就在同一个自建应用里补权限并重新发布，不需要重新开发一套应用。
