### 问题3 定论与修复（runToken 误杀，已修+验证）

**排查链**（全程实证）：
1. 带网络日志复现：SSE 请求 status=200、~26s 正常完成，但 UI 仍"本轮问数已取消"→ 排除网络/nginx。
2. 页面上下文裸 fetch 该 SSE 流：ready→96trace→summary→result(requires_confirmation=false,ds=1)→done 全程正常 → **SSE/后端完全没问题，result 正常送达**。
3. 给 startAsk 加临时 debug 日志复现：全部事件（含 result）被打上 `runToken mismatch cur=1 global=2` 忽略 → startAsk 返回 null → aborted。
4. 给 resetSession/clearRecoveredSessionResult 加调用栈：`clearRecoveredSessionResult()` 在执行途中被调（runToken 1→2），唯一调用点是 SmartAsk.vue onMounted(5541)。

**根因**：onMounted 的 async 体在 `await getBookshelfDatasets()` 时让出执行权，textarea 已可见，用户此时发问 → `startAsk` 立即写入 `state.question`+`status='running'` → 数据集返回后 onMounted 走到守卫 `if (state.question) clearRecoveredSessionResult()` → 误判"残留状态"清掉正在跑的问数 → runToken 失效 → 所有 SSE 事件被忽略 → "本轮问数已取消"。间歇性：手快/数据集慢必现，手慢/数据集快正常。

**修复**：session 新增 `hasActiveAsk()`（= activeAbortController 非空，区分"本页活跃问数"vs"刷新残留"）；onMounted 守卫改 `if (hasStaleRecovered && !session.hasActiveAsk?.()) clearRecoveredSessionResult()`。改动文件：smartAskSession.js（加 hasActiveAsk 导出）、SmartAsk.vue（onMounted 守卫）。
